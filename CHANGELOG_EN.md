### Unreleased

- 🎨 **The "Add to conversation" floating chip now paints from the host's floating-button pair instead of a translucent menu fill**: the old fill (a menu token that is translucent by default) looked white over the Markdown preview but washed out over the code viewer's transparent CodeMirror. It now shares the pair behind DSH's own selection quote action (`@deepseek-ai/dsh-message-quotes`): `--dsw-alias-button-floating-fill` at rest and `--dsw-alias-button-floating-hover` on hover and keyboard focus. Geometry and the flat hairline border are unchanged.
  - 🧪 `tests/theme.spec.ts` gains a case pinning both `.selectionPopup` fills; returning to the menu token or `interactive-bg-hover` now fails the exact-value assertion.

- 🪟 **Floating layers no longer place their own title bar under the desktop shell's native window-control band** (same root cause as [#805](https://github.com/omdsh-dev/DSH-better-sidebar/issues/805)): on Windows the shell paints its native minimize/maximize/close buttons over the top band of the viewport with `titleBarOverlay`, and pointer events in that band never reach the page. The task-detail window (`FloatingWindow`) had a hard-coded 8px top floor with a 34px title bar, so its × landed inside the band and could not be clicked; the node-detail popover (`AnchoredPopover`) and the mermaid zoom toolbar had the same problem. New `src/client/viewport-inset.ts` reads the standard `navigator.windowControlsOverlay` (`visible` + `getTitlebarAreaRect()`, `geometrychange` with a `resize` fallback) and all three consumers keep their interactive area below the band; vertical drag/re-layout floors follow it, an appearing band lifts an already-placed layer, and a disappearing band never pulls it back up (maximize/restore does not move what the reader placed). **Read-only probe, zero configuration**: no CSS variable, no DOM attribute, no preference key, no revival of the `--dsh-title-bar-strip` mechanism removed in #430; a missing API, `visible:false`, or a throwing read degrade to 0, so plain browsers and the web build behave exactly as before.
  - 🧪 Tests: new `tests/viewport-inset.spec.ts` (11 cases); 6 new cases in `tests/floating-window.spec.tsx`; new `tests/anchored-popover.spec.tsx` (3 cases); the mount lane injects a fake WCO and asserts the zoom toolbar's real layout moves 16→52→16.

- **A directory target is no longer read as a file** ([#1029](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1029); same root cause also covers [#933](https://github.com/omdsh-dev/DSH-better-sidebar/issues/933)): when the opened path is a folder (a chat folder link, a `sidebar_open` folder, a directory pasted into the editor address bar), `fs.read` / `fs.readPage` answer with the dedicated `fs-directory` code; `EditorHost` turns the tab into the folder window (`meta.dir: true` + file tree) instead of painting the raw `"…" is a directory` host error into the tab. The promotion resolves a relative target against the session workspace root first and normalizes it to the platform-native spelling (`resolveNativeSidebarPath`: separator dialect + no trailing separator): listing answers are keyed by the host's `path.resolve`'d absolute path while FileTree caches levels by the requested root, so a relative or mixed-separator root would sit on its loading placeholder forever.

### v0.30.1

- 🎯 **The "Side card" settings row no longer shows two icons**: the plugin still assumed the settings navigation had no icon channel, so it hid the fallback gear with CSS and painted its own glyph. The shell has long since exposed a `settings.section.icon` slot addressed by section id, and it now wraps the nav icon in a span — the stale `> svg:first-child` rule stopped hiding the fallback, so both glyphs rendered side by side. The row now contributes its icon **through the slot**, and the marker + CSS-mask apparatus is gone (along with a document-wide MutationObserver).
  - 🧪 `tests/settings-nav-icon.spec.tsx` pins the glyph to the slot-provided `size` and `currentColor`; a headless pass against a real host confirms one `svg` in the row and no leftover marker.

### v0.30.0

- 🧭 **Adapted to DSH 0.2.2-rc.1 (peer floors move to `^0.2.2-rc.1`)**: the host replaced the installable `ModelSelectionRef` with an agent-owned `AgentModel` — `agent.model.select()` records the choice durably and applies it to the next step, so the side-chat thread model selection rides the agent's own handle instead of an installed ref. `dsh-tools` dropped the PTC (`tool/ptc-dispatch*`) event **type declarations** (the runtime still records them), and host icons switched from inline `<path>` to sprite `<use href="#dsw-icon-…">`. **The support line moves with it**: a 0.x caret never spans a minor, so DSH 0.2.1 hosts (`0.2.1-rc.1 ~ rc.5`, today's npm `latest`) keep pinning plugin **v0.28.2** (`v0.29.0` was never published), while 0.2.2-rc.1+ takes **v0.30.0**.
  - 🧪 Verified by `typecheck`, the full `vitest` suite, and `plugin-mount` against a real 0.2.2-rc.1 host in Chromium; see the [0.2.2 adaptation record](docs/plans/2026-11-04-dsh-0.2.2-rc.1-adaptation.md).
- 🧭 **The installers now verify that a profile's own `@deepseek-ai/dsh-*` copies belong to one host version** ([#1107](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1107)): profile-installed host packages resolve ahead of the DSH installation, so the `dsh-subagent` this plugin imports statically binds to a mixed set; a missing export then takes the whole host down with `DesktopHostFatalError: required plugins did not activate`, never naming the package. `scripts/install.sh` / `scripts/install.ps1` now run the shipped `scripts/check-profile-host-tree.mjs` after installing (mirroring DSH's own profile resolution: profile-local copies only, and only the exact `dsh-attachment` peer `dsh-subagent` declares) — a torn pair prints both versions plus the repair and stops instead of telling you to restart. The README FAQ documents the same repair (remove `@deepseek-ai/dsh-*` from the profile's `package.json` / overrides and `pnpm install`, or align both copies).
  - 🧪 New `tests/install-host-tree.spec.ts` (6 cases, running the shipped script: a torn pair exits 1 with both versions; a matching pair, a subagent-only copy, a stale copy above the profile, and an absent plugin all pass; both installers are pinned to call it and the script is pinned into `files`).
- 🧵 **A side chat opened while the parent is mid-turn no longer persists an unreadable child session log** ([#1109](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1109)): once the parent has compacted, the seed is copied around its last compaction checkpoint with **renumbered** seqs, but the inherited `session-log-deepseek/delivery-accepted` `throughSeq` is an absolute seq — it still named the parent's position, so the child carried a watermark that did not precede its own marker. The host's v4 reader treats such a log as corrupt (`SessionFormatError: delivery throughSeq must precede its marker`): the child can never be read again, which also breaks the parent's `includeDescendants` export. The rebase now remaps the watermark, and drops the record entirely when the watermark fell inside the dropped span (there is no child-side equivalent, and inventing one would claim a delivery that never happened). **Already-corrupt logs are not repaired**; only new ones are prevented.
  - 🧪 `tests/sidechat-compaction-seed.spec.ts` adds one case: a compacted parent carrying real delivery markers must yield a seed where every surviving marker's watermark precedes it and still names the same event the parent marked, while markers whose watermark was trimmed away must not survive.
- 🛟 **The native tab close and Desktop Cmd+Q no longer discard editor drafts silently** ([#1072](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1072), [#1071](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1071)): the host's right-column tab strip (× / middle click / context menu / `page.close`) and the Desktop shell's quit expose no confirmable close hook — `registerCloseHandler` is a synchronous cleanup whose only veto is a throw, and Desktop Cmd+Q runs through the shell's own `before-quit` → `app.exitRequested` where the page sees no cancellable event (see [host contracts §C](docs/host-contracts.md)). The editor now throttles the **live document** into `localStorage` (key = `sessionId::path`; 200k characters per draft, 600k total, 8 drafts, FIFO), flushes it in the native close handler and in `beforeunload`, and offers "An unsaved draft was found. Restore it?" when the same file is reopened. Saving, confirming a discard, and confirming a reload / in-place switch drop the backup.
  - 🧪 Tests: new `tests/editor-draft-backup.spec.tsx` (8 cases) and two new cases in `tests/editor-unsaved-guard.spec.tsx`.
  - ⚠️ Host gap: the Electron desktop shell has no `will-prevent-unload` dialog and no cancellable quit hook, so a real save / discard / cancel flow needs a host capability; the guard would then call `confirmDiscardDraft` and this fallback path could go away.

- 📐 **Page CSS zoom is no longer mistaken for a page-level transform** ([#1102](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1102), PR [#1110](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1110)): with `body { zoom: 1.15 }` the panel host's `100vh` resolved to ~932.6px in an 811px viewport, so the geometry self-check switched the host to absolute positioning and grew the document. The expected height now folds the ancestor `zoom` chain while width and offsets keep their thresholds, so a real page transform is still caught.
- 🎛 **The Changes lens switcher uses the public `SegmentedControl`** ([#1098](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1098), PR [#1101](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1101)): it previously painted its own buttons on top of host-private CSS-module hash names and degraded to native browser buttons whenever the host restyled. The private-class dependency is gone.
- 🗂 **A container workspace now shows and switches every child repository**: `git.status` has always reported every discovered root in `repositories`, but the Git panel only listed them in the "More actions → Repository" submenu — no name and no count at the top of the panel, and the body rendered `repositories[0]`, so a workspace holding three projects looked like it had one. When more than one root is discovered, a chip row (`data-scm-repos`, one `[data-scm-repo]` per root) now renders above the Changes section with the current checkout marked `[data-active="true"]`; clicking a chip goes through the existing `chooseRepo`, so reads, mutations and the commit graph stay pinned to the chosen root. A single-repository workspace renders no row, and the existing menu entry stays.
  - 🧪 `tests/git-repo-switcher.spec.tsx` adds three cases: every root listed and switchable, backslash/trailing-slash/case spellings folded to one checkout, and no row for a single-repository workspace.
- 🔖 **Selecting text in the editor now drops a clickable quote chip into the main composer (expanded to a path plus fenced body on send)** ([#888](https://github.com/omdsh-dev/DSH-better-sidebar/issues/888)): in the `code` / `markdown` / `jsonl` editing surfaces and in Markdown preview, "Add to conversation" used to paste the text into the composer; it now inserts a chip owned by a plugin-registered input-trigger source (`betterSidebarQuote` via `ctx.inputTriggers.registerSource`). **Clicking the chip reopens the source file in the sidebar at the quoted lines** and flashes the whole `line`–`lineEnd` span for 2.4 s (skin token `--dsw-alias-interactive-bg-hover-accent`, softened under `prefers-reduced-motion`); on send the source's `codec.serialize` restores the byte-identical `<relative path>[:start[-end]]` header plus a fenced body of up to 500 characters (header only beyond that). The end line reaches the viewer through a module-local one-shot side channel (`src/client/line-target.ts`, keyed by path + line, capped at 32), **never through host navigation params** — the host's `SidebarRightResourceParamsMap.file` only declares `line`.
  - Degradation: no `ctx.inputTriggers` service, a rejected registration, a composer outside an insertable phase, or a stale `draftRev` falls back to the built-in non-clickable chip from #1052, then to plain text, so behaviour never regresses past the previous release. A failed insert deletes the record it just wrote, so no orphan ids accumulate.
  - Records live in `localStorage` (`dsh-better-sidebar:quote-refs`, FIFO of 200) because the module ships in both the core bundle and the lazy editor chunk; the two instances can only see each other's records that way. Clicking validates the chip's session first — a different session may carry a different cwd and would open the wrong file.
  - The chip only opens the right sidebar; **the bottom workbench has no entry for it** (the bottom `TabContent → EditorHost` is the same component and does consume `line`, but this feature has not been verified by hand there). Line numbers are the selection-time snapshot: after the file is edited, a click lands on the same line number (possibly drifted) — no anchor search is performed.
  - New peer `@deepseek-ai/dsh-client-ui-input-trigger` (`^0.2.1-rc.1`, bringing the DSH peers to 14); the integration surface and its three-tier fallback are documented in [guide §7.2](docs/external-plugin-guide.md).
  - 🧪 Tests: new `tests/selection-quote.spec.ts` (27 cases), `tests/quote-flash.spec.ts` (13), `tests/line-target.spec.ts` (8); `tests/conversation-draft.spec.ts` gains 2 cases (the chip's `source`/`ref` override leaves #1052's default payload untouched), and `tests/editor-line-nav-mode.spec.tsx` gains 1 (a second click on the same chip still jumps and still flashes).
- 🪟 **Windows + WSL workspaces: a UNC path is no longer folded into a drive-relative one.** Re-spelling paths on a Windows base folded every run of separators into one `\`, which also folded the UNC prefix of `\\wsl.localhost\<distro>\...` into `\wsl.localhost\...`; the host's `path.resolve()` then anchored that on its own process drive (`C:\wsl.localhost\...`), so every file opened from a WSL workspace failed with ENOENT. The UNC prefix now survives and only the rest is folded (drive paths are unchanged).
  - 🧪 `tests/worktree-address.spec.ts` adds one case: UNC absolute, workspace-relative, and forward-slash spellings all keep the two leading separators.
- 🗂 **A session cwd that is a Git repository subdirectory is no longer lifted to the repository top** ([#1024](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1024), [#1080](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1080); contributor PR [#1070](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1070) @hy5424): the sidebar root was replaced with `git rev-parse --show-toplevel`, so a relative file link in chat resolved to `<repo>/<file>` instead of `<repo>/<subdir>/<file>` (ENOENT) and file search used the wrong root. The session cwd is now the root as it stands; only linked-worktree evidence from the session's own tool calls replaces it. The cwd is canonicalized first, so symlinked spellings (`/var` vs `/private/var`) cannot make a nested worktree look outside the workspace (#952).
  - 🧪 `tests/active-worktree.spec.ts` adds one ASCII and one Chinese subdirectory case (both red before the fix).
- ⚡ **Mermaid previews of large Markdown documents no longer stall the renderer (layout measurement isolated in a sandboxed iframe)**: mermaid measures label text with `SVGElement.getBBox()` against a node appended to `document.body`, so every measurement flushes the whole DSH document layout — measured on a real desktop host at **59–75 ms per measurement** (15,418 nodes) versus **1 ms** in an empty iframe. A 31-diagram document therefore blocked the main thread for >20 s, tripping the desktop shell's surface watchdog and turning tab restoration into a crash loop. Diagrams now render inside a hidden `sandbox="allow-scripts"` iframe (a self-contained blob: document with the mermaid UMD bundle inlined plus a small postMessage protocol); the parent only sends/receives and sanitizes SVG: **per diagram 1,500–7,300 ms → 30–104 ms, 31 diagrams in ~5 s**, while the client mermaid chunk shrinks from **7.04 MB to 3.69 MB**. A shared render queue (visible/near-viewport diagrams first, the rest filled in on `requestIdleCallback`, 16 ms main-thread yields between renders — **every diagram is still rendered, none degrades to a code block**) and fence-line-sized placeholder skeletons complete the change. Design and measurements: [docs/plans/2026-10-23-mermaid-iframe-isolation.md](docs/plans/2026-10-23-mermaid-iframe-isolation.md).
- ⚡ **Smooth scrolling for large documents**: the render queue pauses while the reader scrolls (resuming 350 ms after the last scroll event) and only serves the preview that is actually on screen — hidden tabs keep placeholders and warm their diagrams when shown again. The two mutation-driven full-document scans (inline HTML pass, heading-anchor pass) coalesce bursts into one pass every 80 ms (previously a scan per mutation, measured at 8–15 ms each); initial near-viewport detection reads every rect in one batch before the swap writes, removing one forced layout per diagram; `.mermaidWrap` gains `content-visibility: auto` + `contain-intrinsic-size` + `contain: layout paint style`, so off-screen diagrams leave layout and paint entirely. Scrolling no longer competes with background renders, document-wide scans or off-screen SVG repaint; diagrams still fill in when the reader stops or scrolls them into view — never as code blocks.
- 🐞 **A failed diagram shows the mermaid parse error inline**: instead of only a generic "Mermaid render failed" label plus the source block (the full error was hidden in the hover title), the error strip now prints the first two lines of mermaid's message (e.g. `Parse error on line 10 ... Expecting 'SEMI', ...`), so a broken fence is found without hunting; the full text stays on the title.

### v0.28.2

- 🛡 **A detached session's cwd now comes from its stored workspace address instead of decoding the whole session log.** `sessionQuery.observeSession(..., { projectionMode: 'all' })` decodes the entire zstd artifact and hydrates every projection to answer with one `workingDirectory` string. The real startup fan-out never went through the 0.28.1 `cwdOf()` single-flight (which only covers `/sidebar/api`): the fs-watch socket sends **one frame per watched directory**, and `/sidebar/file|html` resolve cwd per resource, `/sidebar/upload|write` per call — so a 39 MB session was fully decoded dozens of times inside 130–180 ms (the 44-read OOM on 0.28.0 and the 36 reads reported against 0.28.1 are the same path, not a broken dedupe). The cold cwd now uses `sessionPersistence.stat` — a **header-only** read (first zstd frame) with a process-level memo and same-session in-flight sharing — and `activeWorktreeRootOf` returns that address for detached sessions. Once the host attaches the session, the committed `working_directory` and linked-worktree following resume as before.
  - Cost: until the session is attached, the sidebar roots at the original project rather than the agent's last directory/worktree; the next 5 s poll corrects it after attach.
  - 📏 **Measured (40,157,518-byte session, rebuilt locally)**: 12 `session.cwd` + 36 bypass-entry calls concurrently → **1 header read, 0 full reads, 3 ms, +0.3 MB RSS**; the same artifact on the pre-fix build (`43db17f`) with 6 concurrent bypass calls → 6 full reads, +1002 MB peak RSS (≈6.0 GB extrapolated for 36, matching the 6.2 GB incident peak). One full read costs 467 ms / +501.6 MB. Method and limits: [record](docs/plans/2026-10-27-workspace-cwd-over-cold-reads.md) §5.2.
  - 🧪 `tests/smoke.spec.ts` rewrote that group of 8 cases. Rationale and trade-offs: [record](docs/plans/2026-10-27-workspace-cwd-over-cold-reads.md).

### v0.28.1

- **Concurrent single-flight for cold cwd reads (OOM fix)**: after a full restart every session is detached, and the shared cwd resolution behind all twelve `/sidebar/*` routes ran one host observation per call (a full log read plus decode; a 39 MB session × 44 concurrent requests ≈ 1.7 GB → OOM). `cwdOf()` now shares one resolution between concurrent requests for the same session + client cwd hint; there is no TTL (the host already caches completed cold reads by persistence revision), and the hint stays in the key so different hints never leak across each other. Two new `tests/smoke.spec.ts` cases pin "12 concurrent → 1 cold read" and "different hints do not merge".
- **Side Chat** ([#1035](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1035), [#1044](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1044), @NolanHo): local images and deliveries render in the transcript, and a model switch that rewrites the system prompt now trims the seed at the latest summarizing compaction instead of carrying the pre-compaction history into a new thread.
- **No more silent wrong-file writes**: tab reconciliation now reaches tabs opened in **background sessions**, and a worktree session resolves chat links against **one address base**. Renaming or deleting an open file no longer re-creates the old path on the next save, and a relative link inside a linked worktree no longer silently opens a same-named file from another checkout ([#915](https://github.com/omdsh-dev/DSH-better-sidebar/issues/915), [#947](https://github.com/omdsh-dev/DSH-better-sidebar/issues/947), [#950](https://github.com/omdsh-dev/DSH-better-sidebar/issues/950), [#952](https://github.com/omdsh-dev/DSH-better-sidebar/issues/952)).
- **Host crash guard for pathological git output**: the bounded `runGit` reader now latches after the byte cap, destroys both stdio streams and kills the process tree, and budgets stderr too. A pathological worktree can no longer take the whole host down with `RangeError: Invalid string length` ([#999](https://github.com/omdsh-dev/DSH-better-sidebar/pull/999)).
- **Git page**: histories with more than 1,000 branches load again ([#1013](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1013)). **Tags now decorate commits, rows and details** — lightweight and annotated, with their own inventory budget and pagination fingerprint, without consuming the branch limit ([#983](https://github.com/omdsh-dev/DSH-better-sidebar/issues/983)).
- **Editor**: saving after an mtime-only change (a `touch`, `git checkout` or formatter rewrite of identical content) no longer deadlocks on `fs-conflict`; “Reload from disk” adopts the fresh baseline in place and keeps the draft ([#1059](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1059)). The reading position survives tab re-seating ([#965](https://github.com/omdsh-dev/DSH-better-sidebar/pull/965)). “Add to conversation” now lands as a compact reference chip and never flattens earlier chips ([#1002](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1002), [#1052](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1052)).
- **Markdown links**: local destinations normalize Windows backslashes, so `C:\ws\_analysis\report.md` opens instead of a bare ENOENT ([#1037](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1037)).
- **Sidebar**: the bottom-workbench toggle stays visible while the right panel is open ([#989](https://github.com/omdsh-dev/DSH-better-sidebar/issues/989)); the macOS dock fallback avoids the window controls instead of pinning itself to the top-left corner ([#992](https://github.com/omdsh-dev/DSH-better-sidebar/issues/992)); a content-stable tab scope ends needless full-file re-reads ([#1057](https://github.com/omdsh-dev/DSH-better-sidebar/pull/1057)); closing a side-chat tab archives its session instead of leaving a copy behind ([#942](https://github.com/omdsh-dev/DSH-better-sidebar/issues/942)).
- **Package**: export the `dsh-better-sidebar/icon` subpath so other packages can resolve `icon.svg` through `exports` ([#1016](https://github.com/omdsh-dev/DSH-better-sidebar/issues/1016)).

### v0.28.0-alpha.0 (prerelease)

- **Support moves to DSH 0.2.1-alpha.5+**: 13 DSH peers use `^0.2.1-alpha.5`; development dependencies, CI and installers pin the exact baseline. DSH 0.2.0-rc.2 users should pin npm-published **v0.26.1** (v0.27.0 has not been published). Install this alpha explicitly as `dsh-better-sidebar@0.28.0-alpha.0`, not `latest`.
- **Native Connection admission**: HTTP/WS routes delegate to `ctx.connection.requestRejection(req)`, without the removed `webRuntime` service or plugin-owned trust exceptions.
- **Runtime invariants integration removed**: upstream removed `@deepseek-ai/dsh-invariants` and `/invariant` subpaths; the plugin removes its companion, types and package entry. Compaction seed coverage retains the public surface fold and seed validator.
- **Current working directory**: files, Git, terminals and new side chats follow session `working_directory`; live reads use workingDirectory, cold reads use sessionQuery all projections with lease disposal. Linked worktrees stay base-keyed; each new sidechat seed ends with a current-cwd stamp.
- **Companion API / dependencies**: supply `TerminalBlockLabels.commandLine(line)` in both consumers and synchronize all 21 dictionaries; update Cordis `4.0.5`, schemastery `~3.18.5-alpha.2`, group `1.0.5-alpha.2` and include `1.0.10`, without a direct loader pin or overrides. Alpha.5 prefers package `engines.dsh` for compatibility; this plugin leaves it absent and retains its 13 DSH peers.
- **Validation record**: [release integration validation](docs/plans/2026-10-17-alpha-release-validation.md) records 221 files / 2681 passing tests in single-worker mode, real alpha.5 mounting, and all three Context integration variants. The [initial adaptation record](docs/plans/2026-10-16-dsh-0.2.1-alpha.5-adaptation.md) preserves earlier adaptation evidence.

### v0.26.0

- ⚡ **git status polling no longer drags the UI down** (follow-up to [#212](https://github.com/omdsh-dev/DSH-better-sidebar/issues/212)): one fetch is `git status --untracked-files=all` plus two whole-repo `--numstat` diffs — four processes — and on a repository with a large UNIGNORED tree (a nested `node_modules`, a package-manager store) that measured **59,631 entries / 9.24 MB / 0.131 s**, with the 2,000-entry cap only applied AFTER the whole output had been produced and parsed. Three changes together:
  - **the editor's gutter no longer owns the poll** — it passed the feature switch where the tab's visibility belongs, and that parameter is what starts the timer; with native tabs kept mounted, opening any file kept the scan running every 2.5 s for the rest of the page's life. It now reads the shared answer and refreshes only on a file switch or a save, and holds no subscription at all while its tab is parked.
  - **the baseline is 30 s, with automatic back-off** — a round trip over 750 ms / 2 s / 5 s drops the slot to 60 s / 180 s / no automatic timer, a fast answer climbs straight back, and event-driven refreshes (stage, commit, discard, save, manual refresh) stay immediate.
  - **idle polls notify nobody** — the store's version counter is the `useSyncExternalStore` snapshot, so bumping it on every tick re-rendered every consumer once per cadence even when nothing had changed.
  - Linked-checkout inventory counts now use a single cheap command instead of a full `status()` per checkout; an untracked DIRECTORY counts as one entry there (it used to expand to every file, and the number was silently capped anyway).
- 🚀 Plus everything else in v0.26.0: fully streamed transfers with the three deployment caps removed, a read-only paged preview for very large files, a fourth built-in viewer for `.jsonl` / `.ndjson`, Side Chat live push + visible queue + per-thread model selection, multiple bottom-workbench terminal tabs, the rebuilt Tasks panel, native-right-sidebar rename/delete reconciliation, and several silent data fixes. See the [Chinese CHANGELOG](./CHANGELOG.md#v0260) for the full list.

- **Oversized-file preview is now append-on-scroll, the way VS Code's log view works**: the first cut used explicit previous/next paging (each new page REPLACED the current one). Now reaching the bottom pulls the next window and keeps everything already read — line numbers continue across page boundaries, and "load all" is simply append-until-EOF. The walk has to be sequential: each page's `offset` IS the previous response's `nextOffset`. The too-large notice grew a "load all" button (showing byte progress while it works, disabled once EOF is reached).

  Its companion **row ceiling** (`MAX_PREVIEW_ROWS = 50_000`) is the one thing VS Code does not need and this does: its `TextModel` and view are virtualized, so a gigabyte in the model still means a small DOM; this renders real elements. At the ceiling the preview stops and points at the download — a visible cap beats a frozen tab, and it sits far above any log a person reads in a side panel (the 6 MB reference log is ~35k records). The ceiling lives in the reading hook rather than the view's own RENDERED row count, because while `loadAll` walks pages in an `await` loop React has not re-rendered: deciding from a stale number overshoots by several pages. The new spec caught exactly that — the worker OOMs in ten seconds.


> Upload, download, the HTML preview and archive packing all stream now, and there is no size limit left anywhere. The three deployment limit keys `readLimit` / `mediaLimit` / `uploadLimit` are gone with them (a retired key left in an old profile is silently ignored as an unknown field — no migration needed); `listLimit` stays.

- **Downloads have no 20 MB cap and the host's memory no longer grows with the file**: `/sidebar/file` and `/sidebar/html` went from "`readFile` the whole thing → `res.end(buffer)`" to `createReadStream` + `pipeline`. The load-bearing detail is WHEN the header is written — the stream's `open` event is awaited first, so an unreadable file (ENOENT/EACCES/directory) still produces the plugin's JSON error envelope instead of a 200 with an empty body; a failure after that point (the file changed under us, the peer went away) destroys the socket. `writeJson` gained a `headersSent` guard so a route's catch block cannot throw `ERR_HTTP_HEADERS_SENT` on a committed response and turn a truncated download into a crashed request. See `tests/file-stream-route.spec.ts` (a real 21 MiB `node:http` transfer, a mid-stream abort, an unreadable path).

- **Upload's two 128 MB gates are gone**: upload was already streamed end to end (`for await (chunk of req)` → temp file → atomic rename); what stood in the way was the client's `MAX_UPLOAD_BYTES` pre-check and the host's per-chunk `limit` check. The streaming core, the failure cleanup and the "never leaves a partial target or temp file" guarantee are untouched.

- **Packing is the system's job now, not a ZIP writer of ours**: the hand-written 300-line encoder (`src/zip.ts`, with its `ZIP_MAX_BYTES` / `ZIP_MAX_ENTRIES`) is deleted in favour of probing and running the system `zip` (always with `-y` — without it Info-ZIP FOLLOWS symlinks and an `a -> .` loop recurses forever) or `tar` (Windows 10 1803+ ships `bsdtar` and no `zip`). The tool's stdout goes straight into an OS temp file, never into memory, and the download streams it out before the file is deleted. `archive.status` lost its per-entry `done/total` (a child process reports none) and shrank to `{ state, bytes }`; with neither tool installed `archive.build` answers the new wire code `unavailable` and the UI shows an actionable sentence. The client download went back to a plain `<a download>` link — a Blob would hold the whole archive in the tab's memory and undo the host-side change.

- **Saving no longer has a 1 MiB wall**: `fs.write` rode the JSON API, whose request body is capped at 1 MiB, so a file the editor could open could not be written back. Saving moved to the raw `POST /sidebar/write` route (the document IS the request body); the encoding and line-ending restore (#523 / #871) is carried over unchanged and still pinned by `tests/fs-write-route.spec.ts`, now with a case far past the old ceiling.

- **Oversized files get a read-only PAGED preview instead of a truncated editor**: `fs.read` went from "whole file or a truncated prefix" to three outcomes (`text` / `binary` / **`too-large`**). Above the editable threshold (5 MiB) a text file is no longer handed over as half a document — it answers `too-large` with a 4 KiB sniff head, and the client renders a paged read-only preview (a monospace line list, the log-viewer shape) with a download escape hatch. Oversized BINARIES are unaffected (the media path is the same as before). `FileViewerProps.truncated` and the `truncation` copy key are both deleted — "half a document that looks editable" is itself the defect #732 was about. The new `fs.readPage` pages by byte window, trimmed back to the last line break so a page is a whole number of lines; a single over-long line is returned as-is rather than as an empty page (otherwise "next" would sit on an offset that never advances).

- **`.jsonl` / `.ndjson` are supported**: they had no highlighting at all (`lang.ts` had no mapping), and mapping them to `json()` is not free — `@lezer/json` accepts ONE top-level value, so a 400-record file parses into **402 error nodes** (measured). There is now a hand-written per-line JSON tokenizer (one line at a time, no cross-line state, an unterminated string marked outright) behind a fourth built-in viewer, `jsonl`: the PREVIEW is one collapsible card per record (collapsed to a one-line summary, expanding into the host's `JsonTree`) and the EDITOR is the same saveable CodeMirror, behind the preview/edit toggle. Line references (`a.jsonl#L131`) still flip to the editor and land on the line.

- **Fixed an invisible error marker**: `tags.invalid` was `#ffffff` in BOTH schemes — white on white in the light theme. It is the token a JSON/JSONL syntax error lands on, and the reader is supposed to be able to see what did not parse; it is now a red wavy underline.

- **A `stat` failure is a 400 now, not a 500**: the two byte routes let the raw rejection escape as an "internal" 500, which reads as a plugin fault. An unreadable user path is a 400.

- **Paged-read encoding consistency (a regression only a real file would surface)**: the first implementation locked the encoding page 1 sniffed, so a "long ASCII prefix + GBK body" file decided UTF-8 from its first page and decoded the GBK tail into mojibake — while a whole-file read had always decoded it correctly. Only WIDE encodings are locked now (UTF-16/UTF-32 is a property of the file; a page that happens to hold no NUL bytes cannot re-litigate it) while byte-oriented encodings are sniffed per page (a pure-ASCII page decodes identically either way). That is safe because pages are line-aligned: `0x0A` can be neither a UTF-8 continuation byte nor a GBK trail byte. Both directions are pinned in `tests/fs-read-page.spec.ts`.

- New guards: `tests/file-stream-route.spec.ts`, `tests/fs-read-page.spec.ts`, `tests/jsonl.spec.ts`, `tests/jsonl-language.spec.ts`, `tests/archive-tools.spec.ts`, `tests/archive.spec.ts`, `tests/editor-large-file.spec.tsx`. `tests/zip.spec.ts` was rewritten as `tests/archive.spec.ts` alongside the writer it tested; the single real-binary case self-probes and skips when neither tool is installed (so the Windows CI runner without `zip` does not go red).

- Design notes, the comparison against VS Code Web (including the correction that **VS Code does not paginate** — its model is threshold + confirmation + turning tokenization off) and the record of implementation deviations live in [docs/plans/2026-10-11-streaming-transfer-jsonl-preview.md](docs/plans/2026-10-11-streaming-transfer-jsonl-preview.md).

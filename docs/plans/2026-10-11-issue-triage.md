## 七、看板同步与回读校验

```bash
node .agents/skills/issue-triage/scripts/board-sync.mjs --dry-run   # 计划
node .agents/skills/issue-triage/scripts/board-sync.mjs             # 执行（幂等）
node .agents/skills/issue-triage/scripts/board-sync.mjs --verify    # 回读
# → verify: board items=258 expected=158 missing=0 mismatched=0 multi-P-label=0 → OK
```

为让回读通过，本轮修了 `board-sync.mjs` 一处真实缺陷（PR [#919](https://github.com/omdsh-dev/DSH-better-sidebar/pull/919)，base `dev`）：**PR 的继承优先级在来源 issue 关闭后不会被清空**。脚本原先「只在有新值时才写」，于是 `verify()` 自己算出的期望（继承源已关闭 → 该留空）与看板上的旧值永远对不上（首次运行报 23 条 `mismatched`）。现在值不再被期望时改为**清空**，且用 `value:{singleSelectOptionId:null}`（`value:null` 被 schema 拒，`ProjectV2FieldValue!` 非空）——这条坑已记进 `references/gh-gotchas.md`。

## 2. 改动与边界

### A1 任务图滚轮合帧（`src/client/TasksGraph.tsx`）
- 新增 `wheelBatcher` 与 `pendingWheelRef`；事件里以 `pending ?? tfRef` 为基准，先算出新的 `{x,y,k}` 再 `schedule(flush)`；**每一步都先 `clampTf` 再写回 pending**（只夹最终值会在中间步触界时改变落点），flush 后 `setTf(pending)`。
- 背景拖拽期间（pointerdown→release）滚轮直接早退：两种手势都提交整份 transform，互不复合，由拖拽独占。
- `preventDefault` / `stopGlide` / `touchedRef` 仍逐事件；与 pan 共用一个 dispose effect。
- 边界：同帧多次缩放与逐帧应用等价（有专门用例）；达到 `ZOOM_MAX` 后的事件按原逻辑早退。

### A2 停靠文件树零工作 + 单批回屏（`FileTree.tsx`、`use-dir-watch.ts`、`TreePanel.tsx`）
- `use-dir-watch.onStale` 签名改为 `(dirs: readonly string[]) => void`：socket 通知传 `[dir]`，re-arm 传整套目录（内部 hook 契约，非 `service.ts` 公共 API）。
- `FileTree` 用 `visibleRef` 门控加载 effect 与 refresh tick（**不把 `visible` 放进依赖**：回屏刷新统一由 watcher 的 re-arm 负责，避免两条路径各发一批）；`retryDirs` 一次 `loadLevels([...dirs], {force:true})`。
- `TreePanel` 的 `window.focus` / `dsh-sidebar:refresh-files` 监听只在可见时注册。
- `loadLevels` 入口再加一道 `visibleRef` 守卫：可见时发出的折叠链预加载在 park 后才返回、或丢弃应答的自愈重试，都不能在隐藏时继续发请求；回屏的 re-arm 在 `visible` 已为 true 的同一提交里运行，不受影响。折叠链预加载 effect 自身也跳过隐藏态（省掉走树）。
- 边界/已知限制：隐藏树**没有缓存**、且同一个 commit 里 expanded 数组身份也变了时，加载 effect 与 re-arm 会各发一次（2 次，不再是最多 64 次）；正常回屏（数组身份稳定）是恰好 1 次。

### A3 侧聊逐行 rewrite 缓存（`src/client/SideChatView.tsx`）
- `RowSurface.rewrite` 改为接收散文行（`Extract<SidechatTranscriptRow, {text:string}>`）；`WeakMap<row, {text,out}>` 缓存，输入变化为 `sessionId` / `cwd` / transport base（`hostTransportBase()`）；行内 `text` 兜底比对防原地变更。
- 流式行每次是新对象 → 只重算该行；pending/echo 仍走原路径。

### A4 diff 单次解析 + 展开预算（`src/client/diff/DiffFiles.tsx`、`src/client/changes/DiffPane.tsx`）
- `DiffFilesProps.parsed?: ParsedDiff`（untracked 合成文件时忽略）；`DiffPane` 的 header stats 与文件行共用同一解析结果。
- `DEFAULT_EXPANDED_LINE_BUDGET = 2_000`：按 hunk 行数累计，超预算的文件默认折叠（header 的 +/− 仍在）；第一个 source 文件无上限；`DiffRows` 的每文件 600 行上限不变。

### A5 提交图历史窗口化（新 `src/client/changes/git-graph-windowing.ts` + `GitGraphSection.tsx`）
- 纯函数 `windowedRange`：`rowsInView = ceil(viewport/28)`、`visible = rowsInView + overscan*2`、`start` 夹到 `[0,count-1]`、`end = min(count, start+visible)`；上下留白 = 两侧未挂载行 × 28。
- 组件：`scroll` 事件经 frame batcher 合帧读取 `scrollTop/clientHeight`（每帧最多一次 layout 读），`ResizeObserver` 跟随面板高度变化（**只在 `visible` 时持有**，隐藏即断开并取消待帧，回屏重新测量），`useLayoutEffect` 在页长度变化后重读（浏览器夹紧 stale scrollTop 发生在 DOM 提交之后）。
- `data-graph-count` 报整页条数（e2e 用它替代数 DOM 行）；`data-graph-scroll` / `data-graph-spacer` 是测试与 e2e 的稳定选择器；滚动时关闭 hover 卡（锚点行可能被卸载）。
- 已知代价（标准虚拟化）：窗口外的行不挂载 → 浏览器 Ctrl+F / Tab 顺序只覆盖窗口 ± overscan；每行仍有稳定 key（`hashFull`）。

### B1 bundle HEAD（`src/bundle-route.ts`）
- `etagOf` 返回 `{etag,size}`（复用同一 stat）；HEAD 在 403/405/404/304 判定后写 200 + 四个头并 `end()`，**不再为响应体 `readFile`**。
- 口径订正：ETag 是内容 hash，**冷路径（首次/文件变化）仍会读一次文件算 hash**，之后按 mtime/size memo 命中不读。客户端的 HEAD 都发生在其 GET 之后，所以实际路径是热命中；`Spec`/`CHANGELOG` 的措辞已按此收窄。
- GET 行为逐字不变（含 ETag 304）；HEAD 也遵循 If-None-Match → 304。

### B2 active-worktree 事件尾守卫（`src/active-worktree.ts`）
- 缓存项新增 `eventSeq`（解析开始前读取，解析中若有新事件则存的是旧游标 → 下次到期保守重扫）与 `gitResolved`（本次 base 探测是否真的解析到 git 顶层）。
- 到期且 `cached.gitResolved && liveSeq !== undefined && cached.eventSeq === liveSeq` → 续 `expires` 后直接返回；否则走原解析。
- 语义：15s 跟随上界不变（新事件只会在到期后的下一次询问被看到）；无 `seq` 的宿主/分离会话保持旧行为。**非仓库/探测失败不续期**：父目录后来 `git init`、网络盘/权限导致的暂时失败都在下一次 TTL 到期时重探（缓存 `gitResolved=false`）。

## 4. 明确不做（与理由）

- **文件树虚拟化**：`renderLevel` 递归渲染，行模型还带 fold chain、内联重命名、per-level error/truncated、拖放目标与 reveal 滚动；改成扁平 row model 是对 2462 行组件的重写，超出「工作量不太大」，需单独立项（本轮只做「隐藏不干活 + 回屏单批」，这是当前最频繁的浪费）。
- **侧聊 transcript 虚拟化**：行高可变（markdown/工具卡）、贴底流式与锚点跳转耦合，需要测量缓存 + 滚动锚定，属高风险大改。
- `usePolling` / 两个 socket hook 接 `document.visibilityState`：后台标签由浏览器节流，收益在 CPU/电池而非可感知卡顿，且会改全局轮询语义。
- `fs.trees` 请求级总行预算、`fs.read` 5MB 单次 JSON、`media/html` 缺 ETag/Range、`git status` 第 4 个进程、`git.graph` 8 个进程（可并行化但低于感知阈值）。
- 关闭 `keepMounted`、CSS `:has`、perf lane 耗时阈值、第二个 git 轮询器。

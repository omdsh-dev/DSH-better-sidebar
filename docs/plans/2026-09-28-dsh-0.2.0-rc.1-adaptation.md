# DSH 0.2.0-rc.1 适配记录（v0.24.0）

> 状态：已实施。支持线从 `^0.1.7-rc.1` 整体前移到 `^0.2.0-rc.1`（**单线**：0.1.7 用户停在 v0.23.0）。
> 上游发布：[dsh-v0.2.0-rc.1](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.0-rc.1)（npm dist-tag `next`；`latest` 仍是 0.1.7-rc.2）。

## 0. 结论先行

**0.2.0-rc.1 对本插件所消费的全部宿主 API 是纯增量**：19 个被用到的宿主包**零值导出删除**，会话格式与子代理描述符版本未动，CLI 与客户端运行时逐字节相同。因此本版**没有为 0.1.7 写任何运行时兼容分支**——唯一必须改的是 peer 下限（否则宿主启动预检会静默禁用整行）。

## 1. 硬阻塞：caret 跨 minor 不成立

`packages/boot/app-boot/src/plugin-compatibility.ts`（0.1.7-rc.1 起）遍历 profile 行的 `peerDependencies`，对名字为 `@deepseek-ai/dsh` / `@deepseek-ai/dsh-*` 的条目跑
`semver.satisfies(宿主版本, 范围, { includePrerelease: true })`，不满足就 `row.disabled = true`，只在 stderr 留一行 `disabling profile plugin …`。

实测（semver 7，`includePrerelease: true`）：

| range | 对 `0.2.0-rc.1` |
| --- | --- |
| `^0.1.7-rc.1` | **false**（caret 上界展开为 `<0.2.0-0`） |
| `^0.2.0-rc.1` | true |
| `>=0.1.7-rc.1 <0.3.0` | true（显式比较器不带 `-0` 上界） |
| `>=0.1.1-rc.2 <0.2.0` | true（同上，`dsh-whale-report` 正因此仍能加载） |

**教训**：`AGENTS.md` §3.4 第 12 条(c) 那条「`includePrerelease` 让判定更宽松（`^0.1.6-alpha.2` 也能满足 `0.1.7-rc.1`）」**只在同一 minor 内成立**；跨 minor 时必须同步抬 peer 下限。用户已选择**单线**方案，不做「同时覆盖两条线」的放宽范围。

### 5.1 实测踩到的坑：profile 自己的 `pnpm-workspace.yaml` overrides 必须与宿主同步

升级后 3080 出现「加载提供商目录失败: settings service is absent: mount @deepseek-ai/dsh-settings with @deepseek-ai/dsh-config-editor in the profile composition」。宿主日志给出了根因链路：

```
dsh: disabling profile plugin row "config-editor": Plugin @deepseek-ai/dsh-config-editor@0.1.7-rc.2
     is incompatible with dsh 0.2.0-rc.1: peerDependencies {"@deepseek-ai/dsh-hmr":"0.1.7-rc.2",
     "@deepseek-ai/dsh-app-boot":"0.1.7-rc.2"}
settings (@deepseek-ai/dsh-settings): pending (waiting for service: configEditor)
```

profile 的 `pnpm-workspace.yaml` 里有一条上一轮升级留下的 `overrides: '@deepseek-ai/dsh-settings': 0.1.7-rc.2`（它自己的注释就写着「Keep this in lockstep with the host version」）。这条 pin 让 profile 树里的 `dsh-settings` 停在 0.1.7-rc.2，而 `dsh-settings` 用**精确版本**声明 `dsh-config-editor` / `dsh-util-values` → profile 顶层出现 0.1.7-rc.2 的 `dsh-config-editor`，它**遮蔽**了宿主 bundle 自带的 0.2.0-rc.1，于是 0.2.0 的启动预检把 `config-editor` 整行禁用，`settings` 行永远等不到 `configEditor`，设置/模型页的 provider 目录随之失败。

修法：把该 override 与注释一起抬到 `0.2.0-rc.1` → `pnpm install`（profile 内）→ 重启。修复后 profile 顶层全部收敛到 0.2.0-rc.1（`dsh-atomic-write` / `dsh-brand` / `dsh-config-editor` / `dsh-util-values` / agent-team 三包），`.pnpm` 里 0.1.7-rc.2 的副本归零。

**教训（对宿主版本升级通用）**：升级 DSH 时，除了 launcher 的 npx 钉版与 profile 依赖，**profile 自己的 `overrides` / `pnpm-workspace.yaml` 里任何 `@deepseek-ai/dsh-*` pin 都必须同批抬版本**；否则 profile 树里会出现旧宿主包并遮蔽 bundle 自带的那一份，而预检只报「某行被禁用」，症状（设置服务缺失）与原因（一条 override）隔着好几层。

升级步骤（含回滚）见最终交付说明：备份 `~/.dsh/dsh-web.sh` 与 `profiles/web/package.json` → launcher 的 npx 钉版 → `0.2.0-rc.1` → 升 agent-team profile → 装 v0.24.0 tarball → `pm2 restart dsh-web` → 核对路由与 `pm2 logs` 的 `disabling profile plugin` 行。

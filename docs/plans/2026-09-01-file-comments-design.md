# 当前文件评论设计

## 目标

把文本查看器原有的“选区直接追加到主输入草稿”改为可审阅的评论队列：用户选择代码或 Markdown 内容后填写评论，保存到当前会话；在当前文件的独立评论抽屉中集中编辑、删除并一次性发送给 Agent。

## 交互契约

- 编辑器头部的评论按钮紧邻文件树按钮；两者共用侧抽屉几何但视图互斥，不把评论嵌入目录树。
- 评论按钮仅面向当前文件，并显示该文件未发送数量；无文件路径时禁用。
- 同一文件新增评论时自动打开评论抽屉；切换文件只切换数据范围，不因数量差异误触发打开。
- “当前”展示未发送评论，“历史”展示发送成功的评论；发送失败保留当前队列。
- 两个列表进入时均默认全选，可逐条取消，并提供全选、取消、发送和删除；发送只包含发送开始时已勾选的评论，当前列表中未勾选评论继续留在当前队列，历史列表发送表示重新发送且不改变原历史时间。两个列表的批量删除都一次完成持久化和订阅通知。
- 发送进行期间新增的评论不属于本次批次，只按发送开始时截取的 ID 集合归档。

## 数据与发送

- 评论按 sessionId 隔离，独立持久化到 `dsh-sidebar:file-comments:v1:<sessionId>`，不混入布局状态。
- 每条评论包含绝对路径、可选行号范围、最多 500 字符的选区、评论正文、创建时间及可选发送批次信息。
- 超长选区只保留位置，沿用现有 selection payload 的 500 字符契约。
- 发送通过 DSH 0.1.2-alpha.2 的公开、按 scope 寻址的 `conversation.send(text)`；不修改 DSH，不占用或覆盖主输入草稿。
- 本地已发送历史每会话最多保留 200 条；未发送评论不因历史裁剪丢失。

## 影响范围

- `TextEditor`：选区浮层改为评论输入表单。
- `EditorHost`：管理文件树/评论互斥抽屉和未发送徽标。
- `FileCommentsPanel` / `file-comments`：评论 UI、持久化、格式化与归档。
- `conversation-draft`：新增 scope-addressed 直接发送辅助函数，原有草稿追加能力保持兼容。

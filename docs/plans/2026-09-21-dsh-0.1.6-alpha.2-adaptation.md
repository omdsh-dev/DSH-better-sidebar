# DSH 0.1.6-alpha.2 适配（v0.20.0 基线）

日期：2026-09-21　分支：`feat/dsh-0.1.6-alpha.2`

## 背景

DSH `dsh-v0.1.5-rc.2..dsh-v0.1.6-alpha.2`（上游 **1687 个 commit**，中间还有 `dsh-v0.1.6-alpha.1`；`git diff --shortstat` = 5420 个变更文件 / +878 484 / −63 637）是 0.1.6 线的第二个预发布版，也是本插件自 rc.1 以来第一次遇到**真实破坏**的 delta。两件关键的事实构成这版全部工作：

1. **两条插件面向的硬契约收紧，且都是静默失败**（§上游 delta 1/2）；三条 `ui-primitives` 破坏是编译期可见的。
2. **宿主内置了插件原本自研的两个面**（右列终端、右列浏览器）。继续保留就是同一面存在两套实现，并且遮蔽产品正在开发中的宿主类型。

本计划记录该 delta、逐项结论与子系统级落点；上一版记录见 [2026-09-10-dsh-0.1.5-rc.2-adaptation.md](./2026-09-10-dsh-0.1.5-rc.2-adaptation.md)，仓库级适配要点同步到 [AGENTS.md](../../AGENTS.md) §3（本版整体重写，是该节的权威摘要）。

## 决策

1. **peer 下限必须动：`^0.1.5-rc.1` → `^0.1.6-alpha.2`**。semver 的预发布规则要求比较子与候选版本同 `[major,minor,patch]` 元组，`^0.1.5-rc.1` 在数学上**永远容纳不下任何 `0.1.6-*` 预发布版**。实测（用仓库树内的真实 `semver@7.8.5`）：

   | range \ candidate | `0.1.5-rc.2` | `0.1.6-alpha.1` | `0.1.6-alpha.2` | `0.1.6-alpha.3` | `0.1.6-rc.1` |
   |---|---|---|---|---|---|
   | `^0.1.5-rc.1` | true | false | false | false | false |
   | `^0.1.5-rc.2` | true | false | false | false | false |
   | `*`（裸） | false | false | false | false | false |
   | `^0.1.6-alpha.2` | false | false | **true** | **true** | **true** |

   即：0.1.5 的下限不是「保守」而是**结构上不可能**容纳 0.1.6 预发布；`^0.1.6-alpha.2` 天然容纳 0.1.6 的 alpha/rc 全线并排除 0.1.5。
2. **支持线取舍：0.1.5-rc.\* 用户停留在 v0.19.1**。rc.2 → alpha.2 有真实破坏（#1/#2），按本仓库先例（v0.19.0 抬到 0.1.5-rc.1 时直接桥掉 0.1.2 线）**不写运行时兼容层**；0.1.5-alpha.2 及更早同样停留在旧版。`engines.dsh` 与 peer 下限同源（同一个支持范围，两处不能分叉）。
3. **终端整体让位**：删除整套 PTY 栈（见改动清单），宿主 `ui-sidebar-terminal` 成为唯一提供者。**接受模型侧代价并写进 README**：插件原有的 8 个 `terminal_*` 工具（`terminal_create/list/send/read/wait/resize/signal/close`，默认关）是模型唯一的**跨调用持久**终端，而上游等价物 `@deepseek-ai/dsh-tool-terminal` 未被任何 shipped bundle 默认挂载，删除后模型只剩一次性 `bash` / `pwsh`——这是「不维护第二套 PTY」的既定代价，不是意外，所以不补自家的替代实现。
4. **浏览器让位，但保留 DOM 层链接接管**。宿主不做按协议分流（https 默认交系统浏览器），那是插件唯一还能提供的能力，因此 `src/client/link-intercept.ts` 与已发布的 `urlTarget` 机制（v0.13.0+，第三方消费插件按它声明）不动；接管目标改指**宿主的** `browser` kind（`ctx.sidebarRight.openTab('browser', { params: { url } })`），并保留 `window.open` 兜底——宿主没装该包时不至于点了没反应。
5. **轮尾接管整体删除**。list 只能追加，插件再注册一行只会与宿主的产物卡**重复**；上游是有意选 list（「An additive list lets both plugins contribute without either knowing the other's data or rendering」，`.agents/notes/implemented/feature/2026-09-17-persistent-plan-cards.md:27`）。产物行交回宿主，它开文件走宿主 `openFile` → 本插件的 editor，**行为不变**。文件打开的那一半（`sidebar-file.ts`）与路径助手（`paths.ts` 的 `resolveSidebarPath`）保留，因为文件变动 tab 与编辑器宿主仍在用。
6. **guide 条目 id 作为类型契约落进插件侧**：两个条目各自带 `id`（descriptor id / `'files'`），并加测试守护「每个 guide 条目 id 非空且互不重复」。**不做运行时兜底**（自动补 id 会把契约破坏变成永久沉默，正是这次最难查的形态）。
7. **加一条可见的失败接缝**：`registerNativeSurface` 新增可选 `reportFailure(phase, error)`，接到 `src/client/index.tsx` 的 `fail()` 可见诊断条；单个 descriptor 注册失败不再带走其余注册。理由就是这次的症状——整个原生承载面静默空掉，除了一行缺失的指南之外没有任何提示。
8. **卡片采用宿主胶囊配方，但字重走令牌阶梯**：几何/描边/填充/圆角照抄宿主 `GuideBody.module.css` 的 `.entry`（0.5px `--dsw-alias-border-l4` / 24px 圆角 / `--dsw-alias-bg-layer-1` / `min-height: 56px` / `padding: 14px 20px`），标签字号**不抄**宿主那里的裸 `font-size: 15px`（它背后没有令牌），改用阶梯最近一档 `--dsw-font-s-strong-14`（14px medium）。皮肤契约要求插件侧零豁免面（AGENTS.md §5）。
9. **不接入本版新增的宿主面**：`openTabs` / `tabsIn` / `registerCloseHandler` / `preferNewPane` / keyed `guide.entry` 槽 / 全局面板——插件只用到 `multiple` 与既有面。

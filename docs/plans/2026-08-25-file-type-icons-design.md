# 文件类型图标设计（2026-08-25）

> 状态：已实现（分支 `feat/custom-development`）。

## 目标

- 文件树与编辑器、差异 Tab 对同一路径使用同一图标，减少从树到代码区的识别成本。
- 参考 Codex 的文件类型表达：图形优先区分语言、文档、配置、工作流、媒体与未知文件，颜色只作为第二提示。
- 保持 DSH 皮肤兼容，不引入固定品牌色或单独的浅色、深色分支。

## 分类与颜色

- 代码使用品牌色，文档使用成功色，配置与数据使用警告色，工作流与敏感配置使用错误色，未知或二进制文件保持中性色。
- 颜色全部读取 `--dsw-alias-*` 语义令牌；图标来自现有 VS Code 图标族，确保描边与视觉重量一致。
- 完整路径优先识别 `.github/workflows`，文件名优先识别 Git、环境变量、包清单与工具配置，最后按扩展名匹配。

## 接入

- `FileTree` 的文件行渲染共享 `FileTypeIcon`。
- 编辑器与差异 Tab 根据 `tab.path` 或 `tab.diff.path` 渲染同一个 `FileTypeIcon`；无路径的 Files 首页继续使用文件夹图标。
- 未知扩展名回退为中性通用文件图标，不影响打开、拖拽、右键菜单或无障碍名称。

## 验收

- Python、TypeScript、Markdown、包清单、Git 文件、工作流和图片得到稳定且不同的图标分类。
- Windows 与 POSIX 路径得到相同结果。
- 文件树与 Tab 的图标种类、色调一致；隐藏文件、损坏链接和选中状态沿用既有行级语义。

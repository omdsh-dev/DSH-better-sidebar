# 2026-11-12 DSH 0.2.2-rc.1 → 0.2.2-rc.2 适配

> 目标：把插件基线抬到 DSH **0.2.2-rc.2**（npm `next`，2026-11-12 发布），同步 14 条 peer / 30 条 dev 钉版 / CI / 安装脚本 / 文档，并把上游真实的契约变化改到位——**不是只改版本号**。插件版本 **v0.32.1**。

## 2. 上游差异与证据

对 `@deepseek-ai/dsh-*` 的 rc.1 / rc.2 npm tarball 解包，逐包 diff 类型面（17 个直接消费/传递包）并核对以下真实变化。

### 2.1 必须改代码

1. **`Menu` 的定位 API 换掉了**（`@deepseek-ai/dsh-client-ui-primitives`）
   - rc.2 删除 `useAnchoredPosition` / `AnchoredPositionOptions` 与 `Menu` 的 `getAnchorRect`；新增 `anchorRef`（外部触发元素）与 `anchorPoint`（光标坐标 `{x,y}`）。
   - portal 菜单改用 CSS Anchor Positioning；**子菜单改为 `createPortal(..., document.body)`**，按可用空间选 `data-submenu-layout="side"` 或 `"page"`。
   - 迁移指南：`docs/upgrade-guide/v0.2.2-alpha.2/css-anchored-menus`（该 API 在 rc.2 的产物中落地）。
   - 改法：`src/client/changes/GitLens.tsx`（2 处）、`src/client/FileTree.tsx`、`src/client/TabBar.tsx` 的 `getAnchorRect(() => new DOMRect(x,y,0,0))` → `anchorPoint={{x,y}}`；关闭态传 `undefined`。
   - 连带删除已失效的本地 workaround：`src/client/menu-flip.ts`（body 属性 + layout.css 改写子菜单 `left/bottom`）整块移除——rc.2 的子菜单已不在根菜单 DOM 内，旧选择器全部失效，且宿主自己负责放置。

2. **Agent Teams 服务换包**（`@deepseek-ai/dsh-agent-team`，base composition）
   - 旧 `@deepseek-ai/dsh-experimental-agent-team`（opt-in profile）不再发布 rc.2；新包已进入 DSH base composition，Team 模式按会话开启（默认 `enabled:false`）。
   - `TeamService` 删除 `tryMembership` / `listMembers` / `spawnTeammate` / `sendMessage` 的旧 roster 面，新增 `isEnabled` / `setEnabled`；`createTask` / `updateTask` 签名不变，仍以 live member Agent 作授权凭证。
   - `agentTeam` 投影仍是 `{ enabled, tasks, failure? }`（0.2.2-rc.1 的 `members` 早已移除）；插件 `team-projection.ts` 的读路径不需要改。
   - 改法：`src/context-types.ts` 的结构镜像 `tryMembership` → `isEnabled(agent): boolean`，并删除不再存在的 `SidebarTeamMemberView` 镜像；`src/team-routes.ts` 的准入从「membership 命中」改为「`isEnabled` 为 true」，false / 抛错仍映射 404。

3. **依赖收紧**
   - 所有宿主包把 `@deepseek-ai/cordis` peer 从 `~4.0.5` 收紧到 `~4.1.0`；Cordis Core 同步 4.1.0。
   - `cordis-plugin-include` 升到 1.1.0（Cordis 4.1.0 与 `dsh-config-editor` 的 peer 要求）。
   - 新传递 peer `@deepseek-ai/dsh-error`（attachment / llm / working-directory 都声明），必须提升进 devDependencies，否则 pnpm 解析不到 `dsh-attachment` 的类型依赖。
   - 插件只用 `ctx.fiber`、`ctx.loader.entries()`、`Service`，Cordis 4.1.0 的 `Fiber` / `reflect` / `Events` 形状变化不触达。

### 2.2 已核、不需要改的部分

- `SESSION_FORMAT_VERSION` 仍为 **4**；`SUBAGENT_DESCRIPTOR_VERSION` 仍为 **3**。
- `dsh-session` 的批量 `append(inputs)` 新增，但 `session/event` 仍逐条发布（观察者在整批提交后按序收到）；插件没有包装 append，`sidechat-push` / `workflow-routes` / `changes-ops` 的监听不需要改。
- `dsh-tools` 新增错误身份（`ToolContextUnavailableError`、`ToolGuardDenial`、`PostToolDecision.info`）为纯新增；插件不分类错误码。
- `dsh-subagent` 的 `listDescendants` 条目新增可选 `path`，`rootOf` / `namesOf` / `waitForTreeWork` 取代旧方法；插件只读 `listDescendants`，不用旧方法。
- `dsh-client-ui-conversation` 的 `insertQuote(text, summary?)`、`conversation.hero.frame` hoc 槽、composer 新字段；插件走 `insertReference` 与既有槽，兼容。
- `dsh-client-ui-workspace` 的注入面移除 `openWorkspaceMenu` / `openSessionMenu`；插件只读 `openSession` / `startSession` / `archiveSession`（仍在）。
- **macOS app-region 改成显式声明**：0.2.2 对所有元素先 `initial`，只有 `[data-window-drag]` 行是 `drag`，`body > :not(#root)` 仍是 `no-drag`，控件只在 `[data-window-drag]` / `[data-window-drag-controls]` 内才 `no-drag`。插件自己的 body portal 根因此已是 no-drag；mermaid 全屏 scrim 仍 `initial !important`，其按钮计算为 `none`（不形成 drag 盒）。挂载用例的旧断言 `no-drag` 改为 `none`。
- `jobs` 客户端服务、`sessionController.resolveAgent/modelCatalog`、`webTerminals.launchShells/selectShell`、`sessionPersistence` 句柄 API、`workingDirectory` 读取面均未变。

## 4. 刻意没做的事

- **不写运行时兼容层**：`^0.2.2-rc.2` 不覆盖 rc.1，rc.1 用户固定在 v0.32.0（仓库先例）。
- **不补子菜单 tether/hover 高亮**：旧 tether 依赖被删除的 body 属性与嵌套 DOM；改为宿主放置后不再保留（避免全局选择器污染宿主菜单）。

- **不改 `docs/plans/` 里的历史适配记录**（版本号是当时事实）。
- 不修改 DSH 源码。

## 7. 同批补充：插件页图文详情（meta.detail）

DSH 插件页的详细介绍由 `locale/<language>.json` 的 `meta.detail` 指向一个 Markdown 文件，图片相对该文件解析（`@deepseek-ai/dsh-plugin-detail` / `dsh-plugin-manager` 的 `readBundleDetail`）。内置插件（如 `dsh-experimental-forge-bundle`）就是这么放 `docs/DETAIL*.md` + `preview*.svg` 的。

- `locale/en.json` / `locale/zh.json`：`meta.detail` → `detail/DETAIL.md` / `detail/DETAIL.zh.md`。
- `detail/DETAIL.md` / `DETAIL.zh.md`：总览图 + 1–5 编号说明 + 「每会话独立」示意图。
- `detail/overview.svg` / `overview.zh.svg` / `isolation.svg`：独立 SVG（无脚本、无外链、无 `foreignObject`，可被 `<img>` 直接渲染），编号与 Markdown 图例对应。
- `package.json#files` 新增 `detail`，确保 npm 包含详情文档与图。
- 守护：`tests/plugin-detail.spec.ts`（locale → Markdown → SVG 的安全路径、SVG 形态、files 白名单）+ `tests/plugin-meta.spec.ts` 的 tarball 断言（详情文档与每张图都必须真的打包）+ `tests/e2e/mount.e2e.ts` 的「Plugins page can serve the shipped detail document image」（真实 0.2.2-rc.2 宿主的 `/api/plugin-manager/detail-file` 返回 200 + `image/svg+xml`）。

> 这里是**插件自身的详情文档**，与宿主 `Menu` / `agentTeam` 的 API 适配无关；放在同一版是因为用户要求本次适配同时补齐插件页展示。

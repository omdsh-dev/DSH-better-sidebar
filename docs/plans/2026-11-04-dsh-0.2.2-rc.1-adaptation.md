## 2. 上游差异与证据

### 2.1 真实代码改动（必须改代码，改版本号不够）

1. **模型选择换成了 agent 自有的 `AgentModel`**（`@deepseek-ai/dsh-agent`）
   - 0.2.1：`ModelSelectionRef`（`{ current, assembled }`，可变）+ `installModelSelection(ctx, ref)` 把它装成 prompt / request 瀑布。
   - 0.2.2：`Agent` 新增只读 `agent.model: Model`，`select(selection)` **同时** 落盘 `model/selection` 并作用于下一步；`installModelSelection(ctx)` 只剩安装投影服务、返回 disposer。`ModelSelectionRef` 类型已不存在（`dsh-agent/lib/types/model-selection.d.ts`）。
   - 改法（[src/sidechat-routes.ts](../src/sidechat-routes.ts)）：`ensureModelSelection` 返回 `Agent['model']`，首次认领时用线程日志里的选择 seed 一次（`select()` 对同一选择是 no-op，不会重复落盘），之后 `sidechat.model` 直接 `select()`；不再 install，也不再持有自建 ref。
   - **合入后补的一笔**：0.2.1 需要"append `model/selection` + 改 ref"两个动作，0.2.2 的 `select()` 已经把落盘包含在内——两处都留会把每次切换记成**两条**事件。已删掉显式 append，测试改为断言 `select` 收到选择且 `session.append` 未被调用（`7ef1dfa9`）。

2. **PTC 事件类型声明被移除**（`@deepseek-ai/dsh-tools`）
   - 0.2.2 的 `dsh-tools` 产物里 **0 处** `tool/ptc-dispatch*`；`SessionStore.append` 因为没有登记项直接抛 `Cannot read properties of undefined (reading 'publicationEntry')`。
   - `dsh-session` 的 `known-event-types` **仍保留**这两个名字，所以**读取**旧会话（0.2.1 记录的日志）不受影响——插件的文件操作折叠（`src/client/changes/ops.ts`）继续识别它们。
   - 改法：生产读取路径**不动**；`tests/changes-ops-route.spec.ts` 里"用真实 store append PTC 对"的用例删除（0.2.2 无法产生该事件），并在原地写明理由、指向 `tests/changes-ops.spec.ts` 里已有的合成事件覆盖。

### 2.2 宿主内部形状变化（只改测试）

| 现象 | 证据 | 处理 |
| --- | --- | --- |
| 本地链接的 `title` 不再等于原始 destination | `ui-primitives/lib/index.js parseFileLink` 自己解析 `#L8-L15` / `:37` / `:12:5`，文件按钮 `title: file.path` | `sidechat-view.spec` 按宿主解析后的 title 定位，仍断言点击后 `openTab({path,line})` |
| 归档按钮的 hover 提示取不到 | 0.2.2 Tooltip 走 `onPointerEnter` 且检查 `matchMedia('(any-hover: hover)')` | `tooltipOf` 改派发 `pointerover` + stub `matchMedia`；**用户侧行为未变**（锚点是 enabled wrapper） |
| 图标断言取不到内联 `<path>` | `productIcon` 渲染 `<svg data-icon="dsw-icon-…"><use href="#…">` | 断言改到 sprite id（stage=plus、unstage 仍是插件内联 minus），12px 尺寸断言保留 |
| `WorkingDirectoryService.get` 抛 `stateOf` undefined | 0.2.2 把投影注册挪进 `[Service.init]()`，`get()` 读 `register` 返回的 handle | spec 的 fake `register` 返回 `{stateOf}`，并 `await lifecycle[Service.init]!()`；断言未改 |

## 4. 支持线影响（重要）

- 0.x 的 caret 不跨 minor，**一个构建无法同时服务两条宿主线**：
  - DSH **0.2.2-rc.1+** → 插件 **v0.30.0**；
  - DSH **0.2.1-rc.1 ~ rc.5**（也就是当前的宿主 npm `latest`）→ 固定 **v0.28.2**（v0.29.0 从未发布到 npm）。
- 本次适配**不改发版流程**：`dev` 合入 `main` 后打 `v0.30.0` tag 即可。
- 用户侧 profile 的 `overrides: '@deepseek-ai/dsh-*'` 若存在，必须同批抬到 0.2.2，否则旧副本遮蔽 bundle（见 AGENTS §3）。

## 5. 刻意没做的事

- **不写运行时兼容层**（仓库先例）：`ModelSelectionRef` 与 `AgentModel` 同时存在只会让 0.2.1 线更难判断；
- 不删 `use-markdown-surface.ts` 里被宿主抢先解析后变成死路径的 `splitTrailingLineSpec`：`path-line.ts` 仍被原生 tab 地址（`CMakeLists.txt:131`）使用，删它属于无关清理；
- 不动 `docs/plans/` 里的历史适配记录（它们的版本号是当时的事实）。

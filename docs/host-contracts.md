# 宿主契约与沿用至今的适配约束

> 从 `AGENTS.md` §3 移出的深度参考（原 §3.4 第 1–12 条与 0.1.5–0.1.7 历史线中仍然生效的部分）。
> **编号保持不变**：代码、测试与文档里写的「AGENTS.md §3.4 第 N 条」就是本文第 N 条。
> 历史版本已不在支持线内（当前基线 DSH 0.2.1-rc.1，见 [AGENTS.md](../AGENTS.md) §3）；逐条适配过程见 [docs/plans/](plans/) 与 [CHANGELOG.md](../CHANGELOG.md)。

当前适配约束：HTTP/WS 均由 `ctx.connection.requestRejection(req)` 裁决 Host/Origin 与浏览器认证，只有 `undefined` 放行，不读取已删除的 `webRuntime`。alpha.5 同时移除了 `@deepseek-ai/dsh-invariants`、`ctx.invariants` 和上游 `/invariant` 子路径；本插件不再发布 invariant companion。

本次 RC 适配只更新版本与依赖声明，不改变上述行为。alpha.5 → rc.1 上游完整树差异共 355 项、全部为 `package.json`，源码零变化；本次验证见 [RC 适配记录](plans/2026-10-17-dsh-0.2.1-rc.1-adaptation.md)，不复用历史 alpha 测试数字。

## A. 0.1.5–0.1.7 引入、至今仍是现行约束的行为

**历史线**：0.1.5–0.1.7 的适配逐条记录在 [docs/plans/](plans/)（`2026-09-*-dsh-0.1.5/0.1.6/0.1.7-*-adaptation.md`）与 [CHANGELOG.md](../CHANGELOG.md)，**已不在支持线内**，也不写运行时兼容层。下面几条是那几版引入、**至今仍是现行约束**的行为：

- **只读文件预览的让出边界**：插件把 `xlsx xls csv tsv fods pdf png jpg jpeg gif webp svg bmp ico doc docx ppt pptx` 让给宿主 `ui-sidebar-documentpreview`（`src/client/native/index.ts` 的 `editor.canOpen` 认领前拒绝，返回 false 即让给内置 `text` 的 `fallback` 档）；自己只保留三件——`md/markdown`（自带渲染器）、`html/htm`（自带沙箱预览 + `htmlViewerNoSandbox` / `htmlViewerDefaultUnsafe`，宿主没有这两个开关）、`code` catch-all（**可编辑的 CodeMirror + 保存**，内置那几个是只读预览）。**拒绝清单不得宽于宿主渲染器**：宿主没有渲染器的扩展名必须认领，否则点开只有空状态（这是实测过的用户可见回归）；`tests/native-surface.spec.ts` 双向钉住这条边界。**未知二进制不回归**：`.zip` / `.wasm` 仍由 `code` 认领 → 宿主 fsRead 判 binary → head 重匹配无 sniffer → `EditorHost.tsx` 的 `load.status === 'binary'` 兜底渲染下载面板。
- **宿主 `browser` kind 在 web profile 不挂载**（0.1.7 起），e2e 显式断言它缺席（AGENTS.md §2）。
- **外链接管只认领声明了 `urlTarget` 的链接**，其余一律不 `preventDefault`、放行给宿主；认领成功但目标类型此刻不可用时 `window.open(url, '_blank', 'noopener,noreferrer')` 兜底（早先兜底到已被删除的 `'browser'` 类型，而 `openTab` 对未注册类型静默 `return`，表现为链接点了没反应）。
- **`files` kind 由插件接管**，宿主自己的按目录 watch 覆盖不到它 → 插件自持 `src/fs-watch.ts`（宿主侧，每条连接一组 `fs.watch`，150ms 去抖，上限 64 个句柄）+ `src/client/use-dir-watch.ts`（一条 `/sidebar/ws/fs-watch` socket 携带展开目录集，目录折叠即退订，收到通知只丢弃并重列那一层缓存）。
- **测试 harness 与 e2e 的三条既有形态**：`tests/browser-globals.ts` 的 `window` shim 必须提供 `addEventListener` / `removeEventListener` / `dispatchEvent` / `matchMedia`（`ui-primitives` 在**模块求值期**就 `window.addEventListener`，缺了任何 import `service.ts` 的 spec 一个用例都跑不起来）；e2e 的 token 交换走 Playwright `request.newContext()`（`maxRedirects: 0`，以免跟随 303 丢掉 `Set-Cookie`）而不是 Node 全局 `fetch`（宿主静态 fallback 对纯 Node GET 回空体 405 且无 `Set-Cookie`）；devDependencies 要覆盖 dev 树实际触达的全部传递 peer（第 8 条）。
- **幽灵字段 `.current` 不存在于任何宿主版本**（插件侧类型自造过它）：会话身份一律读 `ctx.sidebarRight.mounted`（`ObservableSnapshot<SessionId | undefined>`，只在会话真变化时 set）。`Pending` 队列与 `openTabIn/openResourceIn/closeIn` **必须保留**：它们是唯一能写「未上屏会话 store」的路径（这三个方法在具体 class 上，不在 `ISidebarRight` 接口里，需结构化探测）。
- **插件设置面（`dsh-settings` 重写后的形态，改设置相关代码前先读 `src/config.ts` 头注释）**：命名空间就是插件 Loader 行的 `entry.options.id`，schema 来自 `entry.fiber.runtime.Config`；入口 id 用 `src/index.ts` 的 `ownEntryId(ctx)` 运行时自发现（聚合包会用别的 id 挂同一个包，**不允许硬编码**）。用户偏好并进导出的 `Config` 并标成 volatile——**必须用 DSH 自己的 `@deepseek-ai/schemastery`**：DSH 构建在解析期把 volatile 字段包成 cosmokit `Volatile` 引用，用公开 schemastery 写入会「报告成功、revision 也涨，但有效值永远不变」；且 `.volatile()` 返回副本，标记必须收集返回值。读取用 `describe({ redactSecrets: true })` 按 ns 找（**它只列出「有 `Config` 且 fiber 处于 ACTIVE」的条目**），写入用 `update(ns, patch, expectedRevision)`（`SettingsConflictError` → 409 分支保留）。volatile 与非 volatile 的区别就是「改设置要不要重挂」：Loader 的 `equalExceptVolatile` 跳过 volatile 字段、走 live-commit，**普通字段（4 个限额）保持原来的重挂语义**——新增普通 `Config` 字段前先算这笔代价。还要 `settings.configure({ auto: false }, ctx.fiber)`（否则同一批字段渲染两遍）。**`settings/document-updated` 监听不到，不要写**（它在 settings 自己的 context 上 emit，插件 fiber 是兄弟）——触发点靠客户端每次重读表单时重新求值。
- **会话格式 v4 的两处形状**：`source.kind === 'plugin'` 被硬拒，插件侧一律用 `plugin:dsh-better-sidebar`（与 DSH 自己 v3→v4 迁移产出的 kind 逐字一致，历史 sidechat 会话不丢）；tool 结果消息是 `role: 'tool'` + **顶层** `content` / `isError` / `toolCallId`，转录解析器**必须同时接受新旧形状**——旧分支不能删（历史日志里就是旧形状），只认新形状会静默返回空串。
- **客户端会话快照与宿主客户端服务**：子代理目录读 `SessionListState.projectionsBySession[sid]?.values.subagentCatalog`（`mode` 有 `'unknown'` 新值）；后台任务页直接读宿主**客户端** `ctx.jobs` 服务（`src/client/jobs-client.ts`：`getSnapshot()/subscribe()` 整份快照、`watchRows(sessionId)` 按会话引用计数、`observe(...)` 非消费输出流、`kill(sessionId, jobId)`）——**不要自建 `jobs.*` 路由，也不要用事件回放去读模型已读的输出**（那会动模型的 `job_output` 游标）。

- **会话当前执行目录**：文件 / Git / 终端及新建 sidechat 跟随 `working_directory`，不把 session header cwd 当成当前值。live 读 `ctx.workingDirectory.get(session)`；cold 经 `ctx.sessionQuery.observeSession(..., { projectionMode: 'all' })` 读取，lease 在 `finally` 中释放。同一 base 的 live 目录增量通过 epoch 失效缓存；cold 外进程同 base 变化仍沿用既有 15 s TTL。linked worktree 选择仍按 base 目录记账，不把选中的 worktree 反写为 base。sidechat 继承 seed 尾部盖章当前 cwd，避免旧 seed 的目录事件覆盖新线程的初始目录。
- **终端 label**：alpha.5 的 `TerminalBlockLabels` 新增必填 `commandLine(line)`，两个消费者都要提供，21 份词典同步对应 key。

## B. 宿主契约（原 AGENTS.md §3.4 第 1–12 条）

1. **一次性 token 鉴权**：就绪行 `dsh web: http://127.0.0.1:<port>/?token=<43字符>`（导航换签名 cookie，干净 URL 401）。`e2e-mount.sh` 的 URL grep 必须延伸到空白（`[^ ]*`，否则在 `/` 截断丢 token）；e2e 统一走 `tests/e2e/host.ts`（`parseLaunchUrl` 对裸 origin 直接抛错），带 stamps 导航走 `gotoPage()`（先 addCookies 再直达——token 换 cookie 的 303 会丢弃同 URL 其它 query 参数）。插件 `/sidebar/*` 路由不受影响，同源 fetch 照旧。
2. **Remote gateway 斜杠 RPC（唯一方言）**：`POST /api/workspace/create`，payload 恰为 `{args: {...}}`，**args 按控制器 TS 参数名包装**（`workspace/create`、`session/create` → `{args:{request:{...}}}`；`session/list` 的参数名 `_request` **不可省略**——`{}` 也被拒 `args fields do not match the descriptor`）；envelope `method` 与路径一致，点分路径 404。构造由 `tests/e2e/host-protocol.ts` 的 `rpcAttempt` 提供、`tests/e2e-host-protocol.spec.ts` 锁定。
3. **`MarkdownText` labels 嵌套契约**：必填 `labels: { code: { copyLabel, copiedLabel, toolbarLabels? }, footnotes }`（漏传回退硬编码中文）。全部渲染点（`SideChatView.tsx` / `TaskWindow.tsx` / `changes/DiffPane.tsx` / `changes/CommitDetails.tsx` / `mermaid.tsx` / `MarkdownHtml.tsx` / `TextEditor.tsx` 七个文件）统一走 `src/client/markdown-labels.tsx` 的 `markdownTextProps()`。`labels.code.toolbarLabels`（`{codeLabel, wrapLabel, unwrapLabel}` 三个必填串）传了才渲染宿主新的 code card（语言名 + 换行开关 + 复制），插件**全面采用**并复用宿主同一套措辞，所以 `MarkdownCopyLabels` 是 5 个字段，每个构造点都要给全（`tests/mermaid-markdown.spec.tsx` / `tests/markdown-html-render.spec.tsx` 的 fixture 一并同步）。**配套的坑**：新 card 对没有语法高亮的语言（mermaid 正是）显示 `codeLabel`，**info string 不再进 DOM**，`src/client/mermaid.tsx` 因此改为按**围栏正文**匹配——`splitMermaidBlocks(text)` 得到的正文集合 vs `block.querySelector('code')` 的文本，两侧 `trimEnd()`。`DiffBlockLabels` / `ReadBlockLabels` 继承 `CodeToolbarLabels` 且**没有** `files` 字段。
4. **侧边对话（sidechat）**：转录走自有路由 `sidechat.events`（`src/sidechat-routes.ts`），**不碰客户端宿主 RPC**——`ctx.connection.api`（含 `sessions.history`）已整体移除，继任 `session/follow|page` 又对 `origin:'subagent'` 会话强制 subagent 地址（普通 `{kind:'session'}` 被 `agent-busy` 拒）且分页 `throughSeq` 不得超当前游标。live 读 `agent.session.snapshotEvents()`，冷读走 `sessionPersistence` 的**句柄 API**（`open(id,'read')` → `read()` → `close()`；`inspect` 早在 0.1.5 就被删除，注释里再写它属于历史残留）。**实时增量不在日志里**：`assistant/chunk` 事件已删除，进行中的模型增量由 `agent/assistant-stream` 瞬时帧发布（`start`/`chunk`/`end`，不入会话日志），结算时才落 `assistant/message` 或 `assistant/attempt`；插件在宿主侧用 `src/assistant-live.ts` 折叠成有界缓冲。v0.25 起另有两条腿：**实时推送** `/sidebar/ws/sidechat`（`src/sidechat-push.ts` 把 `session/event` 与 `agent/assistant-stream` 去抖压成纯失效帧 `{threadId}`，客户端收到才带 `afterSeq` 重拉，协议面最小且断线自愈，客户端轮询降级为 15s 兜底）；**排队可见**（`sidechat.events` 增返 `pending` = `agent.inbox.nextStep/nextTurn` 投影，`sidechat.dequeue` 按 id 撤一条或不带 id 清空；判定要同时看 `boundaryDelivered` 与 `boundaryPending`，否则「首问未 claim 时连发第二条」会注入第二对 boundary+question）。**模型选择**：宿主对 `origin:'subagent'` 会话**显式禁用**自带选择器（`modelDirectories.assertAvailable`），且 `sessionController.selectModel` 被 subagent fence（`session/agent-busy`）挡，插件因此自建 `sidechat.models`（直通 `ctx.get('sessionController').modelCatalog()`，缺失即 `available:false` → UI 只提供「继承主对话」）+ `sidechat.model`（见第 10 条）。**隐藏与「完整普通会话」在宿主层面互斥**：`ArchivedSessionGate` 会对归档会话（及其 subagent 后代）的 `agent/pre-step` 直接 reject，客户端只按 `origin:'subagent'` 过滤、没有别的隐藏机制——侧边对话只能是「隐藏会话 + 插件自建原生等价表面」。同理**宿主没有 live fork 原语**：`ctx.sessions.fork` / `session/fork` / `dsh-subagent-fork-in-process` 都是某一时刻的冻结前缀副本，子会话永远收不到父会话后续回合。
5. **`dsh-subagent` 的 `SUBAGENT_DESCRIPTOR_VERSION` 仍是 3**：sidechat 种子的 `subagent/descriptor` 版本由宿主包盖章，插件不硬编码；测试断言跟随常量（`tests/sidechat-routes.spec.ts`），勿钉字面量。
6. **`@deepseek-ai/dsh-client-runtime` 包已消亡**（继任 seed 是裸名 `dsh-client-store`，无 `/client` 子路径）：peerDependencies、devDependencies、`dsh.client.inject`、chunk externals 白名单（`src/client/chunk-loader.ts` / `tsdown.config.ts` 各有一处说明它已移除的注释）**无活引用**。
7. **e2e scratch profile 的 `minimumReleaseAgeExclude` 含 `'@deepseek-ai/*'`**（字面配置在 `scripts/e2e-common.sh` 的 `e2e_write_profile` heredoc，`e2e-mount.sh` / `e2e-aggregate-mount.sh` 都调它；与仓库根 `pnpm-workspace.yaml` 同策）：alpha 版本常在发布后 24h 内跑 lane，pnpm 11 的 `minimumReleaseAge` 默认会拒装新鲜包。
8. **插件开发树的 dsh-* 传递 peer 需提升为 devDependencies**：npm 上的宿主包把姊妹包（`dsh-attachment` / `scope` / `session-projection` / `system-prompt` / `user-approval` / `util-time` 等）声明为 peerDependencies（由宿主 bundle 树统一提供，插件仓库没有），插件若只直接依赖其中一部分，其余 peer 在 pnpm 下会解析到树上残留的旧版——测试加载即崩。因此 devDependencies 需涵盖 dev 树实际触达的全部 peer，与直接依赖同款精确钉版；**一律以 `pnpm peers check` 的实际输出为准，不要预加**（`dsh-workspace` / `dsh-agent-preset-registry` 只是 `dsh-subagent` 的 optional peer 且从不被 import）。当前伴随依赖为 Cordis `4.0.5`、schemastery `~3.18.5`、group `1.0.5` 与 include `1.0.10`；不直接钉 loader、不设 override，Cordis peer 下限为 `^4.0.5`，dev 精确 `4.0.5`；与 RC 宿主及传递 loader 的范围一致；`cordis-plugin-group` / `-include` 是 `dsh-app-boot` / `dsh-config-editor` 的**传递 peer**，只改 `dependencies` 不够（pnpm 会继续沿用 lockfile 里的旧副本），要**显式钉进 devDependencies** 才收敛。例外已消除：`dsh-client-locale` 与 DSH 同 tuple，不再允许落后。
9. **右侧栏是 DSH 原生栏，插件只提供 tab 类型**（**编号提示**：旧文与代码注释里把它引用作 `§3.10` / `§3 第 10 条`——`tests/native-surface-cross-session.spec.ts` 的 `§3.10` 与指南 §10 表格里的「第 10 条」都指本条）：聊天里一切文件打开（工具行 / 产物行 / 正文提及 / 行内代码路径）统一走 `ctx.sidebarRight.openResource(fileAddressFor(sessionId, cwd, path))`，其中文件地址语法为「一律 session 作用域、绝对路径保留前导 `/`」，`parseFileAddress` 前缀解析并去 `?`/`#`。插件的每个 `TabDescriptor` 注册成原生 tab 类型（`kind = descriptor.id`，`extension` 带）+ 原生 tab 体（`sidebar.right.pane.tab` keyed 槽，key = `dsh-better-sidebar:<id>`）；`editor` 类型同时认领 `dsh-resource://file/**`（**但按本文 A 节的清单让出一部分**），并接管内置 `files` 页面 kind（`openTab('files')` 打开插件文件树，注销即复位）。`ctx.sidebarRight.openTab/openResource/close` 只对**在屏会话**写入，跨会话用具体类上的 `openTabIn/openResourceIn/closeIn`；原生 tab 的插件侧状态在 `src/client/native/tab-adapter.tsx`。几条硬事实：
   - **注册必须等服务、不能等槽声明**：原生栏先声明 `sidebar.right.pane.tab` 再 `provide('sidebarRightTabs')`，真机 profile 上槽声明回调里 `ctx.get('sidebarRightTabs')` 仍是 undefined（实测 3 秒后才出现），按槽触发注册会静默什么都不注册且永不重试——用 `ctx.inject(['sidebarRightTabs'], cb)` 驱动类型注册（`tests/native-surface.spec.ts` 以「槽先触发、服务后到达」的顺序守护）。
   - `SidebarRightGuideEntry.id` **必填且同 provider 内唯一**（缺它会静默清空整个承载面）；同 provider 的 guide 条目是**追加**关系（`chain` 那种「替换宿主条目」的语义只存在于 `conversation.chat.turnTail` 且已被上游改成 `list`）。**指南只描述 ≤4 条条目**（`GuideBody.tsx` 的 `MAX_DESCRIBED_ENTRIES`）：更长是整列丢弃而不是截断——插件默认贡献 4 个 guide 条目（文件 / Git / 任务管理 / 侧边对话），加上宿主终端条目后可能超限；插件**不恢复**旧的 `nativeGuideDesc` 通用兜底句。
   - `tab.visible` 语义是 `active && (...)`（全局面板 / 后台会话时 body 不挂载）；持久化校验也收紧（非根 / 列轴 / 嵌套 / 3+ docked pane 的 split 一律判非法**整份丢弃**）。全局面板（根级 `main` keyed 槽 + `sidebar.panellist` + `ctx.layout.selectPanel/beginNavigation`、`rightbar` 改根级并新增 `rightbar.session`）插件**不接入**，只做兼容。底部工作台的中心列锚点认 `[data-slot="main.conversation"]`（并跳过 `display: contents` 祖先，同时保留 `[data-slot="conversation"]`）。原生 tab 体宿主 `.paneBody` 是**有确定高度的块级滚动容器**（非 flex 容器），native 适配层因此给每个 tab 体包一层 `height:100%` 的列 flex 宿主（`sidebar.module.css` 的 `.nativeTabHost`），tab 组件根继续用 `flex:1` / `height:100%`。
   - **原生注册账本的两条不变量**（`tests/native-registration.spec.ts` 守护）：① `live` 里同时装着描述符类型（键 = descriptor id）与 `files` 接管（键 = `FILES_KIND`，**永远不在 `wanted` 里**），清理循环必须**跳过 `FILES_KIND`**——它只由编辑器类型的 `wantsFiles/hasFiles` 开关分支与 seat disposer 管理；否则每次通知都会把它拆掉再重建，而 teardown 期间的那次重建会把 id 孤儿化：`tabs.register` 建在**宿主** ctx 上（宿主 ctx 此时仍活着）所以照样成功，紧随的 `ctx.slots.inject` 建在**插件** ctx 上却抛 `cannot create effect on inactive context`，`live.set` 永不执行 → 该 id 在整页生命周期内不可再注册（真机表现：`native register files error: … already registered` 刷屏 + 文件树落到宿主空态，只有刷新页面才恢复；实证见 [docs/plans/2026-09-28-native-files-takeover-reload-leak.md](plans/2026-09-28-native-files-takeover-reload-leak.md)）。② 因此「注册成功一半」是**可达状态**：任何在宿主取走 id **之后**失败的注册（槽位注册抛错等）必须**回滚释放该 type** 并释放已经建好的槽位，插件侧只留一个下次通知可以重试的失败，绝不留下无处释放的 id。相关断言必须写在注册表的**事件日志**上而不是「活着的 id 集合」上：孤儿 id 会让键集合看起来完全正常，键集合断言在未修复代码上同样通过。
   - **原生 tab 的状态保留（已采纳 `keepMounted: true`）**：宿主因此把访问过的 body 挂住，同会话切 tab 不再卸载，组件态（树滚动、未保存草稿、chip 重命名）随之免费保留，**不需要**任何 module-level 记忆。三条必须同时成立的配套事实：(a) **记录不能随卸载删除**（只由 `surface.close` 与「会话消失」回收），而「切回会话清零」那一路（真机日志里 `DISPOSE type …:files` → `register`、同键 `drop`+`mint`）已由上面的 `FILES_KIND` 守卫挡掉（真机 e2e 现断言跨会话 `scrollTop` 复原）；(b) 原生 tab id **每会话各自计数**（`tab1`…）且多会话同号并存，记录与写面一律按 `sessionId::tabId` 记账，`Surface.update/has/activate` 的 `sessionId` 缺省按 `sidebarRight.mounted` 解析，多会话同名时**拒绝而不是猜**；(c) **展开集的权威在插件 store 的会话状态里**（`attachStore` + `syncExpanded` + `getSessionStates().expanded`，由 `native/index.ts` 绑定），记录只负责**身份**与投影——两套持久化会互相打架，插件不自持「每记录的展开集」。设计过程与实测见 [docs/plans/2026-09-25-native-tab-state-retention-keepmounted.md](plans/2026-09-25-native-tab-state-retention-keepmounted.md)。
10. **自定义种子必须带 fork 标记对（`meta.isSeeded: true` + `inheritedEventCount`），且 create 后必须 `inbox.clear()`、冷恢复必须按 id 精确清扫——标记对必要但不充分**：dsh-session 契约规定「只给 seed 不标 isSeeded，种子算重放历史而非继承前缀」——缺标记时 `Session.ownEvents()` 含整个种子，子会话的 inbox 折重放种子里的 `agent/inbox/spliced`，**继承父会话切割时刻未领取的 inbox 输入**。**但运行时 inbox 不走 `ownEvents()`**：`ReactLoopInbox.current()` → `ctx.sessionProjections.stateOf()` → `SessionProjectionRegistry.cellFor` 折的是 `snapshotEvents()` **全量日志（含继承种子前缀）**，且标准 inbox 投影的 `init` 忽略 `inheritedEventCount`、注册表 `session/created` 急切初始化跳过一切种子会话（seq ≠ 0）——种子里的 `agent/inbox/spliced` 会原样重放进子会话 live inbox。因此 sidechat 宿主 `agents.create` 成功后、任何 inject/followup 之前必须 `handle.agent.inbox.clear()`（durable 补偿 splice 是 own 事件，冷恢复折存储日志同样归零）。**幽灵的来源比「父会话排队」更宽**：父会话 mid-turn 且工具有未返回调用时，种子被截断在 `turn/start` 之前，而 inbox 的「领取」splice 发生在 `turn/start` **之后** → **父会话本轮开头已领取的输入**在种子折叠里仍是 pending；`clear()` 是唯一能一次清干净的硬围栏（create 时本线程自己不可能有排队输入）。**冷恢复不能沿用 `clear()`**（会误杀「用户在线程里排队、宿主重启后尚未领取」的合法输入）：改为 `dropInheritedGhosts`——`inheritedPendingIds(log, inheritedEventCount)` 只折继承前缀得到幽灵 id 集合，再逐个 `agent.inbox.remove(id)`，精确且幂等（`src/sidechat-core.ts` 纯函数，`tests/sidechat-core.spec.ts` / `tests/sidechat-routes.spec.ts` 守护）。宿主 `session.fork`（api-session-controller）的调用即规范形态（注意：宿主自己的 `fork` **没有**这一步补偿，同窗口有同样的暴露面）；回归由 `tests/sidechat-seed-validation.spec.ts`（真实 `Session.create` + 对 `ownEvents()` 跑 inbox 折 + **真实 `SessionProjectionRegistry`** 折全量日志钉住上游洞与 clear 补偿）守护。**模型选择同为 agent 作用域**：`sidechat.model` 必须同时落 `session.append('model/selection', …)`（宿主 `selectForNextRequest` 的同一形状）与 `installModelSelection(agent.ctx, ref)`（`@deepseek-ai/dsh-agent` 公开导出），否则控制器缓存的 per-agent selection 永不回读投影；resume 后也要按日志里的有效选择重装（`src/sidechat-routes.ts` 的 `ensureModelSelection`）。**上游 0.2.0 新增的 `buildForkSeed` 与本插件手工的 `buildSidechatInheritance` 职责重叠，但收益不明确**（插件另有 dangling-tool-call 退回结构化快照的自有需求），暂不替换。
11. **`dsh.plugin.json` 从来不是 DSH 契约**（全树 grep 0 命中）：DSH 真正读的是 `package.json` 的 `dsh.bundle.patch` + `dsh.client`（`platform`/`inject`/`immediately`/`external`）+ `exports["./client"]`。`dsh.plugin.json` 与 `lib/client-registry.js` 只服务第三方 registry（社区市场）通道，`tests/manifest-consistency.spec.ts` 守护的是这条通道的形状，不是 DSH 契约。**不要混淆两个 manifest 的 `engines.dsh`**：当前宿主的兼容性检查优先读取 `package.json#engines.dsh`，存在时由它独立裁决；本插件未声明此字段，仍由 13 条 DSH peer 决定兼容性。`dsh.plugin.json#engines.dsh` 只是第三方 registry 元数据，不能替代 package 字段；`dsh.manifestVersion` 也不是版本兼容性开关。`dsh.bundle.patch` 有形状校验（非法值会 `throw`，引导期跳过该 bundle），本插件是合法的单字符串。
    **插件展示元数据**（Plugins 页与 `plugin_manager` 列表，v0.21.1 起已采纳）三条硬规则：`package.json#icon` 必须是**包内相对路径**且写进 `files`（36×36、纯填充无描边、**双色渐变**——与 DSH 自带 `PluginArtwork*` 同风格，单色版在 30px 行内尺寸下会读成一块纯色板）；`locale/en.json` 是发现基线（缺它整个目录都不读，`meta.title` / `description` 在这里）；`exports` 必须暴露 `./locale/*.json` 与 `./package.json`。**所有失败都是静默的**——元数据有问题只会退化成一行纯文字，没有任何报错；`tests/plugin-meta.spec.ts` 守护「声明了就必须发布出去」。plugin-manager 侧另有**多 registry 回退**（配置源 → `fallbackRegistries`，默认含 `registry.npmmirror.com`；`network`/`timeout`/`not-found`/`no-matching-version` 会自动问下一个源；`registry` 入参只存在于 Web 对话框与 `plugin_manager` 工具，**CLI 没有 registry flag**）。
12. **宿主版本兼容性是启动期硬约束**：当前宿主先读插件 `package.json#engines.dsh`；字段存在时只按该范围判定，DSH peer 不再拓宽或收窄结果。字段缺席时回退检查名字为 `@deepseek-ai/dsh` 或以 `@deepseek-ai/dsh-` 开头的 peer，按 `semver.satisfies(宿主版本, range, { includePrerelease: true })` 判定。本插件刻意不新增该字段，仍由 13 条 DSH peer 的 `^0.2.1-rc.1` 支持线约束，optional peer 没有豁免。`engines` 非对象或 `engines.dsh` 非字符串会导致兼容性清单不可读并拒绝加载；`workspace:` 仅在 peer 中有效。安装与 profile 启动拒绝可能禁用整行，需读 `disabling profile plugin` 日志；拒绝记录字段已由 `peers` 改为 `requirements`，其中 key 为 `engines.dsh` 或回退检查的 peer 包名。`pnpm peers check` 校验的是 dev 依赖树，不能证明宿主启动预检通过。[官方升级指南](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.1-alpha.5/docs/upgrade-guide/v0.2.1-alpha.3/plugin-engines-dsh/guide.md)。

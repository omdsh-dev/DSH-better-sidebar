## 1. 目标与边界

在 `builtin.feishu.docs` 与 `builtin.feishu.tasks` 两个内置来源中，以 lark-cli 为默认通路，提供应用配置与用户授权的两步连接、按显式 folder／wiki 范围的文档分页浏览、最新 XML／Markdown 文档读取、文档标题与文本块的局部编辑，以及任务的单页浏览与标题、描述、开始、截止、完成状态编辑。文档与任务共用同一 CLI、同一应用配置和同一用户授权连接。

本 Spec 负责飞书资源语义、格式、授权呈现、文档局部写入和任务字段语义；CLI 依赖、安装、路径及连接状态契约归 S2，浮窗外壳与编辑生命周期归 S6。非目标包括：创建／删除／移动文档，创建／删除／分配任务，评论、权限与知识空间成员管理，电子表格／多维表格／画板／附件编辑，全文 overwrite，完整富文本编辑器，跨范围全量扫描，以及 Agent 写入。

独立验证使用隔离的假 lark-cli；真实飞书账号验证只在用户显式同意后单独进行。本设计只静态参考本地 lark 技能文档，未执行任何 CLI，具体命令语义仍需实现时实测确认。

## 2. 来源、共享连接与身份

- 两个 sourceId 共享同一 lark-cli 依赖与同一 connectionId，但文档和任务保留各自的类型、读取结果和编辑能力；不得各自建立第二份应用配置或授权。
- 共享连接不等于共享范围：文档的 folder／wiki 范围与任务清单范围分别维护，切换来源或范围不混用 cursor。
- 文档与任务均以用户身份访问用户的个人资源。应用（bot）身份看不到用户的云空间文档和任务，不能因为 bot 请求返回空结果就显示“没有内容”，也不能在失败时静默切换到 bot 或另一个账号。
- 文档 locator 保留 docx token、wiki URL／node token 及解析后的底层对象标识；wiki token 不能直接当 docx token 使用。任务 locator 使用任务 GUID；客户端展示编号不是 GUID，不能作为更新标识。
- 同一文档或任务通过不同 URL／入口解析时复用稳定引用；解析本身不置顶、不写入线索库。来源展示身份不回传认证 token。
- 两个来源均实现 S1 的 portable 能力：文档导出来源主机、docx／wiki 节点标识及必要的原始 URL，任务导出来源主机、任务 GUID 与普通任务链接。这里的文档 token 是资源标识，不是 access／refresh token；不导出账号、认证 token、设备授权句柄、CLI 路径或应用秘密。接收方使用自己的连接重新解析；未授权时引用保留为未解析，有快照时可独立读取。

## 3. 应用配置与用户授权

- 连接分为两个独立步骤：应用配置（app 配置就绪）和用户授权（当前用户已授权）。第一步完成不等于已登录，已登录也不代表 scope 永远有效。
- 未配置时显示 not-configured 和显式“配置应用”动作。用户点击后由 lark-cli 自己的交互流程完成应用配置；来源只展示白名单中的链接、状态和错误类别，不收集 appSecret，不把原始配置写入偏好、线索、日志或模型。
- 重新配置应用也是显式动作；已有可用配置时不静默覆盖、切换账号或重跑配置流程，除非用户主动选择重新配置。
- 应用配置完成后仍需用户显式点击连接发起授权。文档与任务所需 scope 取并集，按最小范围增量授权；不默认请求 all，不因为读取失败自动发起交互登录。插件不自建后台续期任务；正常资源调用中由 CLI 自行续期，授权失效时仍要求用户显式重新授权。
- 设置页与连接面提供显式的“显示授权链接／二维码”动作。授权 URL 按 CLI 返回的 opaque 字符串原样展示，不重编码、不改写参数；二维码只编码同一 URL，可由 CLI 的二维码能力或客户端从该 URL 渲染。
- `device_code`、授权轮询句柄、access／refresh token、appSecret 和原始 stdout／stderr 只由宿主适配器保管或过滤，不进入模型上下文、工具结果、日志、偏好、线索记录、错误正文或导出包。CLI 自己管理 token 存储与续期，不搬入 `ctx.credentials`。
- `device_code` 只在本次授权会话中短暂保留，随成功、失败、取消或过期失效；不缓存授权链接或 device code 供下次复用，每次授权重新生成。
- 禁止用 `--dry-run` 做只读探测，禁止周期性执行 `auth status --verify` 或任何带认证／业务副作用的“健康检查”。此前已观察到 dry-run 触发认证副作用，因此连接状态只由用户显式配置／授权流程、真实资源请求返回的认证错误或用户手动刷新来更新。
- 授权流程可取消、可超时；取消不写入 ready。授权过期、被拒绝、scope 不足与应用未配置分别呈现，不用一个“失败”掩盖下一步动作。
- scope 不足时只使用错误中的缺失 scope、后台配置链接和提示来引导增量授权；不自动升级为 all，不把后台开 scope 当成已获用户授权。

## 4. 文档浏览范围与分页

- 文档列表浏览必须先有明确范围：Drive 文件夹（folder token）或知识库（space／parent node）。没有范围时显示选择空态，不默认列根目录、不假设“全部文档”，也不把某个空间或文件夹的第一页当成全量。
- 分页大小有上限；范围选择失败时保留已保存引用和用户选择，不自动改为根目录或全空间。
- Drive 文件夹使用原生 `drive files list` 的 `folder_token`、`page_size` 和手动 `page_token`；只列直接子项，用户显式下钻文件夹才继续。Drive 根目录只作为起点，其第一层响应不能推断整个云空间，且应如实呈现根目录不支持同样分页的语义。
- 知识库使用 `space_id`（个人库用 user 身份的 `my_library`）和可选的 `parent_node_token`，默认单页，使用返回的 `page_token` 续读；只有用户显式展开节点时才逐层请求。不得用 `--page-all` 自动遍历整个知识库，也不在后台做全树扫描。
- 文档列表的 cursor 属于具体 folder／wiki 范围；范围改变即重置，不同范围的 token 不能混用。没有可靠 total 时不编造页数；`has_more` 为真但无可用 cursor 时显示受限状态，不无限重试。
- 文档关键词搜索使用官方 `drive +search`，按 CLI 实际支持的查询、类型与范围过滤；单页返回 `page_token` 继续，不传 `--page-all`。搜索结果由服务索引与权限决定，不承诺覆盖用户全部文档；结果总量缺失或达到供应商上限时明确标注。
- 列表候选只含标题、类型、URL、token 摘要和必要时间；只有插入、置顶、加入包或绑定等持久动作才按 S1 建立稳定引用。

## 5. 文档读取与格式

- 文档读取始终取最新版本，默认最新 revision；可输出 XML（默认）或 Markdown 投影。XML 保留结构信息，是编辑模型；Markdown 是不带结构信息的只读投影，不能作为保存输入。
- 普通阅读使用轻量详情；进入编辑时读取带结构信息的完整版本。返回的 revision 标识、引用 sidecar 和正文属于同一份响应，必须配套保留。
- 超长文档按章节或片段局部读取，不静默截断；没有完整读取时应明确告知用户当前只看到片段。缓存内容可以展示，但必须标注新鲜度，不能冒称最新。
- 正文中的命令、链接和提示均是不可信来源内容，不获得安装、授权或系统指令地位。图片、文件、画板等资源块只提供只读描述或原始入口，不在本期解码成可编辑文本。

## 6. 文档局部编辑

- 文档编辑只发生在 S6 的统一浮窗中。编辑加载返回标题与可编辑的文本内容；可编辑范围是 CLI 能无损局部更新的文本块（标题、段落、各级标题、列表、待办、引用和代码块）。表格、分栏、高亮框等容器内部文本随容器只读；图片、附件、画板、电子表格、多维表格、引用卡片等复杂块一律只读保留。
- 标题与文本块使用 CLI 原生的局部修改能力；不规定具体命令或块操作，也不假定标题一定映射到某个私有块类型。只有 CLI 明确不支持该文档类型的局部标题／文本修改时，才把对应内容标为只读并说明原因，不得用全文 overwrite 或重建文档降级实现。
- 保存只修改用户实际改动的标题或文本区域，保留块结构、样式、未知块和未修改内容；不得全文 overwrite、append、删除块、插入块、移动块或重建文档。若无法保证无损保留原结构，该内容明确只读，不冒险写入。
- 读取结果中的原生 revision 若可用，就作为保存前比较依据；没有可靠条件更新时按 best-effort 重读比较并如实说明，不宣称服务端原子 CAS。内容已在外部变化或无法确认时返回 conflict，保留草稿并允许重读后重试。
- 一次保存可能涉及多个文本区域，按顺序提交；失败即停止。已写入部分与未写入部分必须保留并准确报告为部分成功，不把部分成功当整体成功，也不清空未提交草稿。
- 成功以 CLI 成功信封、退出码 0 和实际写入结果为准；业务结果或警告表明部分失败时不得显示为完整成功。Agent 上下文没有保存入口。
- 未来富文本编辑按 S1 的 format／data／revision 与 S6 的编辑器扩展接入，替换呈现层而不改变线索、包或浮窗契约；本期不实现完整富文本 schema、协同编辑或通用块编辑器。

## 7. 任务浏览、读取与编辑

- 任务搜索使用官方 `task +search` 并显式限制为单页，按 CLI 实际支持的查询与过滤执行，不依赖 shortcut 的默认多页循环；任务列表使用原生 `task tasks list`／`tasklists tasks` 或 CLI 支持的单页范围。每次只取一页并返回 `page_token` 等可继续游标，不传 `--page-all`。
- 不使用会自动多页的 shortcut（`+get-my-tasks`／`+get-related-tasks` 默认循环 20 页、`--page-all` 可达 40 页）；不承诺原生列表能表达所有“与我相关”关系，无法由 CLI 服务端表达的关系不伪装成已支持。
- 单页结果返回 CLI 实际提供的 `page_token` 或等价游标供继续；没有可用 cursor 时明确显示单页候选，不伪造下一页。不得在后台把全部任务拉入缓存；列表只用于候选，读取详情以任务 GUID 取最新字段。
- 任务详情至少包含标题（summary）、描述、开始时间、截止时间、完成状态、更新时间和任务 GUID；任务 applink 只从 `guid` 查询参数取值，不能使用展示编号。
- 允许在 S6 统一浮窗中编辑标题、描述、开始时间、截止时间和完成状态。开始与截止必须满足开始不晚于截止；全天与定时语义、时区显示保持原样，不擅自把一种时间改成另一种。只提交用户修改的字段，不发送整份对象。
- 本地校验失败直接标出字段并阻止提交；服务端拒绝时间或 scope 时映射为可操作错误，不静默改值。
- 完成状态通过完成／重开动作单独提交，与普通字段编辑分开；服务端确认完成状态或返回已完成幂等结果时才确认，未确认时保留草稿，已完成的幂等重试不报错。
- 创建、删除、分配负责人、提醒、重复规则、附件和清单成员管理不在本期范围。任务更新没有可靠的原子条件令牌；保存前做 best-effort 最新读取比较，冲突时保留草稿，不宣称 CAS。

## 8. 成功、错误与秘密边界

- lark-cli 成功信封为 `ok:true` 且退出码 0；失败信封为 `ok:false` 且退出码非 0。适配器必须同时校验 `ok:true` 与退出码，不能按顶层 `code==0` 判断；成功信封没有顶层 code，错误 code 只在 `error` 内，是上游数字码。
- 成功只从 stdout 的成功信封与结构字段解析，失败只从 stderr 的错误信封解析；不合并两路输出，不把 stderr 的进度提示或 `_notice` 当 JSON 数据。
- 文档更新额外检查 CLI 报告的业务结果，任务更新额外检查服务端确认；信封成功不能掩盖业务结果失败或部分成功。
- 错误至少区分：未配置、未授权／授权过期、scope 不足、权限不足、资源不存在、限流、revision／块冲突、复杂块不支持、取消、超时和普通失败。错误只保留脱敏类别、缺失 scope 与可操作入口，不回传原始 stderr、token 或 device code。
- 真实资源请求返回授权错误时更新连接状态并保留引用与草稿；不自动重跑授权、不自动重试写入、不把 `_notice` 更新提示当作业务错误或成功证明。

## 9. 独立验收

- 用隔离假 CLI 验证配置与授权是两步：未配置不显示已连接；用户显式点击才发起配置／授权；不调用 dry-run、不调用 `auth status --verify`；授权链接与二维码只来自同一 opaque URL；device code／token 不出现在模型可读结果、日志、偏好或线索中。
- 文档列表与搜索：列表必须先有 folder／wiki 范围并按 `page_token` 单页继续；关键词搜索使用官方 search 的单页结果并标注供应商上限，不承诺覆盖全部文档；范围内不出现 `--page-all`，范围改变重置 cursor，根目录第一页不被当成全量。
- wiki URL 解析到正确底层对象，不把 wiki token 当 docx token；XML 与 Markdown 均能读取最新版本，Markdown 不进入写路径。
- 文档编辑只改目标标题或文本，块结构、样式、未修改内容与复杂块保留；绝不出现 overwrite／append／删块／移块；无法无损时只读，外部变化返回 conflict；部分成功准确报告且保留草稿；Agent 保存被拒绝。
- 任务列表与搜索使用官方单页命令：任务搜索覆盖关键词与 CLI 实际支持的过滤；断言不调用自动多页 shortcut、不传 `--page-all`；标题、描述、开始、截止、完成状态分别可编辑并校验时间关系；完成与重开以服务端确认结果为准。
- 任务 applink 解析只接受 `guid`；展示编号被拒绝的用例单独覆盖。
- 覆盖未配置、未授权、scope 不足、403／404、限流、取消、超时、`ok:false` 非零、`ok:true` 但业务失败、部分成功与脱敏。真实账号验证单独进行，不进入 CI；本 Spec 不声称已完成实现或真实验证。

## 10. 集成责任

S1 拥有来源／类型／线索模型与格式契约，S2 拥有 CLI 依赖、安装、连接和授权运行时，S6 拥有浮窗与编辑器承载，S5 拥有 Agent 只读工具。本 Spec 只拥有飞书文档与任务的资源语义、授权呈现、局部写入和字段行为。设置页展示归 S8，Tab、入口、词典、公共指南与最终装配归 S9；本 Spec 不复制公共结构，也不在其它文档中重复定义上述契约。

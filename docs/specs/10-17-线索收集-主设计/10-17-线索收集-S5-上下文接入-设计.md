## 1. 目标与边界

让侧栏插入、输入框 @、工作区绑定与 Agent 读取使用同一套稳定引用。默认只提供引用及统一获取方式，正文在需要时读取最新版本。

不新建会话访问许可表、临时资源票据、Agent 写入工具或第二套聊天输入框。会话、子代理、恢复的历史会话都可以通过相同本地 API 读取有效引用。

## 2. 引用协议

本期文本协议固定为 `[[dsh-clue:<id>]]`、`[[dsh-cluepack:<id>]]`，以及显式快照引用 `[[dsh-clue-snapshot:<snapshotId>]]`。id 与 snapshotId 来自 S1，不编码凭据、认证环境变量、CLI 命令或临时文件位置。可附人类可读标题；标题是元数据，不是指令，转义后不得破坏 token 边界。

引用、纯文本复制、草稿恢复和发送序列化必须采用同一标识。重命名、置顶状态、会话变化、分页或认证续期不得更换标识。工具读取包时获取当前成员，不把包变成永久冻结的正文集合。

公开 Agent 工具为：

| 工具 | 语义 |
|---|---|
| `sidebar_clue_list` | 查询来源、线索或包；允许工作区／来源／关键词及分页筛选，工作区只是查询范围，不是读取授权 |
| `sidebar_clue_read` | 按 kind（clue／pack／snapshot）与 id 读取；pack 返回当前成员及可用快照标识清单，clue 调用原始来源读取当前内容，snapshot 从本地快照库读取明确的历史内容及获取时间 |

普通 clue token 永远选择 live 读取，导入快照不能改变该选择。live 读取失败时返回原错误及可用快照标识，不能自动用旧内容替代成功结果；用户或 Agent 可以显式选择 snapshot。pack 返回的快照标识只是可选择的历史版本，读取包不自动把所有快照正文塞入上下文。缺少原始来源或授权时，snapshot 仍可由相同本地工具读取，清楚标识历史时间与完整性；其引用不经过远端鉴权。UI 从快照页面点击 @ 时插入 snapshot token，从实时资源页插入 clue token，避免无意更换语义。

工具声明解释上述 token 与读法。缺省查询当前会话工作区，但允许显式查询其他本地工作区；不要求模型先在某个会话登记 id。工具在插件可用时统一注册，主会话和子代理可见，恢复会话不需要重建一份历史许可账本。

工具返回只包含来源内容、必要元数据和稳定错误。依赖、安装、登录、写入与凭据操作不是 Agent 工具。HTTP／CLI／MCP 的真实调用都经来源服务，不在工具实现中复制供应商客户端逻辑。

## 3. 显式插入与 @

### 3.1 两个入口一致

- 包主体点击插入包引用，底条进入管理；单条线索有明确的 @ 按钮；这些操作只修改输入框草稿，不发送消息。
- 新插入条目先确保 S1 稳定引用存在。失败保留原草稿并提示，不能先显示一个永远无法解析的临时 id。
- 使用宿主公开 inputTriggers／输入引用能力插入和序列化，不把非文件线索伪装成宿主文件路径，不自绘第二套 @ 菜单。
- 一般点击单条线索标题进入详情，@ 按钮专门负责插入。与包主体的快捷插入语义在 UI 上明确区分。

### 3.2 宿主候选与序列化

核心注册稳定的来源入口 `better-sidebar:clues` 与 `better-sidebar:packs`。具体业务来源由核心入口聚合，避免关闭／卸载一个业务来源后，已在草稿中的引用失去 codec。

- 空查询优先给本地置顶与包；不因打开 @ 就拉取所有远端资源。
- 非空查询按开启的来源能力查询，限制并发并支持取消；某个来源失败不清空其他结果，错误可定位到来源。
- 来源图标／名称沿用 S1，在宿主公开候选呈现能力内显示。引用 chip 的 appearance 只能使用宿主公开支持值，不伪造新字段或改宿主 DOM。
- 默认 serialize 只生成引用文本，不读取远端正文、不触发认证检查，避免发送消息被远端请求阻塞。
- 已保存的稳定引用即使对应来源关闭，也仍可序列化；来源关闭不等于读取权限取消。插件缺失而无法恢复宿主 codec 时明确保留草稿并报告不可用，不悄悄丢弃引用。
- 所需宿主服务缺席时显示明确不可用状态，不能无提示丢点击，也不能退回发送含 token 的 shell 命令。

## 4. 包含内容的显式选择

普通默认始终为引用。用户可以在插入选项中显式选择“包含内容”；这与未来按类型强制正文的策略不同，后者本期不实现。

此模式在发送时通过来源获取正文，生成有来源、读取时间和新鲜度标记的文本投影。发送前可见内容体量；失败、超限或部分资源不可读取时保留草稿并说明，不能静默删条目、截断或改成仅引用后继续发送。

二进制或无法直接文本化的内容不得伪装成已内联全文；使用宿主支持的资源入口并明确标记，不能把二进制 base64 填满消息。此模式不承诺新增宿主附件协议；分享文件的完整二进制快照由 S7 处理。

## 5. 工作区绑定自动注入

绑定的是线索或包。用户在内部管理界面配置；为此工作区建立新会话时，首次模型执行前自动提供引用清单与工具读法，不提前拉取正文，不等待远端授权。

- 归属通过宿主 workspaceId 解析。创建时成员关系尚未落入 workspace.sessionIds 时，允许通过会话初始 cwd 和宿主工作区解析服务得到归属；不能误用当前全局上屏会话。
- 普通主会话与同工作区新建子会话采用相同本地规则。不建立“父会话已允许哪些资源”的限制。
- 使用持久化上下文消息／宿主公开注入点标记本次已提供的引用，遵循仓库会话 source kind 契约，不使用已被拒绝的裸 `plugin` kind。
- 同一创建阶段重入不会重复注入；resume、compact 或切换 Tab 不被当作新会话。
- 从种子／fork 继承的绑定标记同时记录工作区身份与有效绑定清单的修订／指纹；同工作区且清单未变时不重复附带。目标工作区不同、清单已变或缺少标记时提供当前绑定，已有相同引用去重。该标记只防重复注入，不作为读取权限。
- 已存在会话不会因为后来新增绑定而被后台补发一条消息。需要时用户在该会话显式插入；新增绑定对之后的新会话生效。
- 注入后读正文仍取来源最新版本。更新绑定不删除历史消息；解绑不使旧引用不可读。

绑定包时提供包身份及当时可自动附带的成员引用；对包与单条绑定重复成员去重。关闭来源的成员不在新的自动引用清单中，包结构不被修改；显式读取包仍可看到完整当前成员，因为来源开关不是权限边界。

绑定信息从持久库读取，不依赖 keepMounted UI，也不需要 Tab 曾被打开。空绑定不添加空白说明消息。

## 6. 生命周期与错误

历史引用的可用性依赖原始资源存在、来源插件可用、CLI／连接可用和平台权限有效，而不是消息年龄。不能给引用加过期时间或在“访问记录”淘汰后拒绝读取。

来源不存在、CLI 缺失、授权过期、资源被删等错误使用 S1/S2 的分类，附可操作的设置／来源标识，不返回秘密或认证原始输出。已关闭但仍加载的来源可读取历史引用，不执行重新开启 UI 的副作用。

候选请求按菜单可见性取消并忽略过时结果；缓存有界，持久 id 不受缓存清理影响。注册与注销跟随 Cordis 生命周期，HMR 后不会重复 @ 分组、工具或自动注入监听。

## 7. 验收与测试

- 侧栏 @ 与键盘 @ 产生相同稳定引用；只进草稿，不发送；输入位置、原有正文和引用恢复符合宿主行为。
- 默认发送不读远端、不触发 CLI 授权；包含内容模式的失败保留草稿，成功标明来源和读取时间。
- 置顶、取消置顶、关闭来源、卸载后重装、会话闲置、服务重启及恢复历史会话的语义符合本 Spec。
- 用预置快照夹具验证 clue token 仍取 live、snapshot token 只取指定历史内容、live 失败不静默回退，以及来源缺失时 Agent 仍可显式读 snapshot；不依赖真实 ZIP 导入器才能完成独立测试。
- 主会话、子代理、同工作区 fork、新工作区 fork、resume、compact、创建监听重入、无 UI 会话和空绑定均覆盖。
- 在真实目标版本宿主中验证注入顺序、持久标记、@ codec、客户端服务注入与取消，不以类型检查代替宿主行为证据。
- 运行工具只能查询／读取；工具参数、返回、注入文本及日志不含凭据、环境变量引用或安装命令。
- 测试隔离真实 CLI 配置；Agent 数据可含恶意文字但只作为不可信来源内容，不获得安装、写入或系统指令地位。

## 8. 集成责任

本 Spec 拥有 token、工具名和上下文行为；S9 的 Tab、S8 的开关以及 S1 的公共客户端动作调用同一实现，不复制引用拼接。总入口与公共指南的集中接线归 S9。遵循 [宿主契约](../../host-contracts.md)。

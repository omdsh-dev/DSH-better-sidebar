## 1. 目标与范围

通过扩展名 `.cluepack` 的标准 ZIP 文件分享一个或多个线索集合，接收方导入为自己的独立集合。支持仅引用与获取方式、包含内容快照两种模式。

不建设在线分享、共同编辑、同步、分享链接、权限服务或可执行安装包。导入不要求原发送方在线。

## 2. 公共文件格式

本 Spec 唯一拥有 `.cluepack` 协议。ZIP 根文件 `manifest.json` 的格式版本为整数 `formatVersion: 1`，同时声明 `format: "dsh-cluepack"`、导出时间 `exportedAt`、模式 `mode`（`references` 或 `snapshot`）、`sources`、`clues`、`packs` 与 `issues`。

| 区域 | 必要语义 |
|---|---|
| sources | 包内 sourceKey，提供者插件标识、来源标识、类型标识及无秘密的来源描述 |
| clues | 包内 clueKey，sourceKey、标题、来源的 portable locator；可选 snapshot 描述；无法移植时保留状态与原因 |
| packs | 名称与有序 clueKey 成员列表；包内去重，不嵌套 |
| snapshot | 归档内相对路径、媒体类型／内容格式、字节数、SHA-256、获取时间及可用的来源版本 |
| issues | 与包内对象关联的失败／缺失记录及稳定原因，不包含原始认证错误 |

`snapshot` 是每条 clues 记录的可选字段，不是顶层映射；每条记录在一个导出包中最多关联一份选定快照。导入后由 S1 分配本地 snapshotId，不沿用包内路径作为运行时标识。实际内容放在 `content/` 下，每个对象通过包内键关联；用户标题、URL 或本地文件名不能直接用作未经校验的解压路径。数据采用 UTF-8 JSON 元信息；二进制正文按原字节保存。JSON 扩展字段可忽略，未知 formatVersion 明确拒绝，不能猜测新版本含义。

这些包内键仅负责一次归档的关联，不充当接收方的运行时全局 id。S1 定义运行时引用身份，导入器建立包内键到本地引用的映射。

## 3. 可移植引用与连接映射

来源通过 S1 的 portable 能力产出可移植 locator。它必须足够描述如何由接收方自己的来源连接定位资源，例如 GitHub 主机／仓库／资源编号、飞书文档标识、工作区相对文件位置。

- 可以携带插件名称及普通使用说明，不能携带可执行脚本、任意 shell 命令或自动安装动作。
- 不包含 token、cookie、私钥、CredentialRef、环境变量秘密映射、CLI 认证目录或发送方连接的认证配置。
- 私有资源的 URL／标题本身也可能敏感；导出确认面展示将携带的资源信息，让用户决定分享范围。
- 接收方匹配自己的来源及连接，不能假设同名 connectionId 表示同一账号。多连接不明确时由用户选择。
- 本地工作区相对文件可以映射到用户选择的接收工作区。外部绝对路径只作为明确标注的来源线索，不自动访问接收机器同路径；需要显式重映射。
- 无 portable 能力的来源导出时明确列为未解析；有快照时仍可分享快照，不能假造可重新获取的引用。

## 4. 两种导出模式

### 仅引用

保存集合关系、标题、来源描述及获取方式，不读取并打包正文，不把已有缓存顺手塞进包。接收方读取原资源时使用自己的授权。

### 包含内容

用户确认后按来源读取内容，存为有获取时间的快照。线索包只是集合，导出器不能因为一个成员可读就宣称整个包都已包含正文。

- 逐项显示进度、取消、失败和不可导出内容。
- 明确导出范围：文本正文和来源可导出的资产；外链资源、评论、PR diff、嵌入画板等没有被实际取得时不能称已包含。
- 可导出原文件字节的本地资源保留原始字节；结构文档保存来源声明的结构格式及可用文本投影，不通过 Markdown 回写原始资源。
- 某项失败时不静默完成。用户可以重试、取消，或明确接受带 issues 清单的部分导出；下载提示及导入摘要均标识不完整。
- 导出取消或失败不留下可被误认成完成品的归档。

## 5. 导入行为

导入先检查并展示摘要，包括包名、成员数量、来源需求、快照情况、未解析项与目标工作区；用户确认后提交。不得在预览阶段自动执行来源读写、CLI 安装或授权。

- 支持来源已安装、来源缺失、未授权和仅快照四种实际情况。
- 缺来源的引用保留为未解析，日后安装／配置来源后可以重新映射，不把数据丢掉。
- 快照可离线查看，明确显示“导入快照”和获取时间。导入预览及快照页不自动联网；用户在该页面显式选择查看原始来源时才读取实时内容，失败保留快照，不能冒称最新。这一 UI 默认不改变普通 live 引用的读取语义。
- 已有同一资源可以复用规范化本地线索；内容作为 S1 中独立的持久快照关联该线索，不覆盖已有 live locator、正文或默认读取模式。新导入包建立独立副本，不静默覆盖同名包、工作区绑定或置顶偏好。
- UI 与 Agent 均可显式按 snapshotId 读取离线内容。具体 token／工具选择由 S5 定义；导入服务本身只需提供 S1 快照元数据及读取能力，不依赖 S5 实现。包成员清单可显示对应的实时引用与可用快照，不把原始资源不可达等同于快照不可读。
- 导入不继承发送方的工作区自动绑定，不默认让所有成员置顶。接收方自行设置。
- 不把快照内容写回原文件或远程文档。快照本期只读；用户若要保存为本地文件，必须显式选择目标并经过现有文件保存流程。
- 提交失败保留原库，不能只导入半个包又返回完整成功；已确认的部分导出本身可以完整导入并保留缺项状态。

## 6. 最小必要验证

导入只接受所支持的格式、合法成员关联和归档内路径。拒绝绝对路径、路径穿越、逃逸符号链接、重复清单条目和内容校验不匹配。解压前检查文件数与展开体积，并在运行时遵守明确资源上限；超限说明原因，不无限占用内存。

这些是正常文件导入约束，不形成按会话授权或密钥隔离系统。实现可使用适合跨平台的归档库，不依赖 Windows 必然安装 zip，也不为此创建系统级安装副作用。

## 7. 验收与测试

- 两模式往返测试：集合顺序、成员去重、非ASCII标题、多个包复用同一线索、二进制字节及结构格式保持。
- 仅引用导出证明没有正文与秘密；快照导出证明真实获取时间、校验和与部分失败清单。
- 来源不存在、连接不同、授权失效、本地路径重映射及离线打开快照均可用隔离夹具独立测试。
- 已有 live 引用后导入同资源的旧快照，原引用仍读取 live，快照按独立 snapshotId 返回历史内容。缺来源／授权时，核心快照读取仍可用；通过 Agent 工具的同等测试由 S5/S9 集成验收。
- 恶意 ZIP 路径、错误版本、断损内容、资源超限、取消与提交失败不写出目标区域、不损坏原库。
- 导入全过程没有执行包内命令、安装插件／CLI、发起授权或覆盖原始资源。
- Windows／POSIX 路径、长文件名、中文及空包有确定结果。

## 8. 集成责任

S7 提供导入／导出业务服务及可被 UI 消费的预览、进度和结果，不依赖真实来源页面。S9 将动作接入包管理与 Tab，S8 不另建第二份分享配置。协议文档与版本归本 Spec 所有，公共指南最终由 S9 集成。

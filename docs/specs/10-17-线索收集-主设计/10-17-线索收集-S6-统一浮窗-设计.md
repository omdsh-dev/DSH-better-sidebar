# S6 统一浮窗与编辑承载设计

**日期**：2026-10-17  
**状态**：待用户批准  
**主 Spec**：[线索收集主设计](10-17-线索收集-主设计.md)  
**依赖**：[S1 来源与线索基础](10-17-线索收集-S1-来源与线索基础-设计.md)

## 1. 目标与边界

把已有持久 FloatingWindow 打磨为来源插件可复用的公开承载能力，改进默认尺寸、标题栏、工具区、正文、导航与窄屏行为，并接入来源自己的内容预览／编辑器。

不是恢复旧版本已删除的自绘右侧面板或自由窗口系统，也不重新定义原生 Tab。任务详情与后台输出等现有调用方复用同一外壳，原有生命周期与功能保持。

## 2. 公开承载契约

客户端在 `ctx.betterSidebar.windows` 提供 open 能力，返回可更新、聚焦和关闭的 handle。公开选项表达稳定窗口身份、标题、内容渲染、内容尺寸预设、标题动作、底部动作及关闭前的草稿处理；不要求来源插件复制 portal、拖拽、缩放与 z-index。

- open 同一窗口身份时聚焦已有实例，不能重复创建并丢草稿；身份由调用方按资源／业务窗口定义，不等同于原生 Tab id。
- 更新只改变内容与显式声明的展示状态；流式数据、刷新或重新渲染不能重置用户的窗口位置与尺寸。
- 来源通过受支持的客户端服务注册其预览／编辑内容，不跨插件 value-import 内部组件。
- 窗口的卸载与所属插件生命周期一致；handle 关闭后重复更新／关闭有明确无副作用语义。
- API 文档应说明它与已移除的 `floatWindows` feature 不同，不重新宣称旧接口恢复兼容。新增能力探测名称为 `windowHost`。

组件内部的状态组织与具体 hook 不在本 Spec 规定范围。

## 3. 尺寸与视觉

初始预设：集合／包窗口约 720×560，文档及编辑窗口约 880×640，小型配置窗口采用适合表单的紧凑尺寸。它们是默认目标而不是绝对尺寸，必须受当前视口及安全边距约束。

- 不再对所有内容统一套用 70%×60%。默认居中；调用方确有锚点需要时可使用锚点，但整条标题栏和关闭操作必须可达。
- 支持拖动、缩放、最大化与还原。还原恢复此前位置与尺寸；调整视口后钳制到可用区域，不把窗口移出屏幕。
- 小屏／窄视口使用近全屏形态，内容滚动，标题与主要操作保持可达。不能靠缩小字体解决溢出。
- 标题栏只放身份、导航与窗口控制；资源动作放工具栏；保存、取消、插入等主要操作放稳定动作区。正文宽度、滚动区和长标题行为明确，不重复堆多个大标题。
- 遵循 DSH 的图标、字体、边框、圆角及层级；视觉参考主题为 #3388BB，组件消费宿主风格的主题令牌。只在悬浮面使用阴影，不新增渐变光球或营销装饰。
- 所有按钮具备 tooltip／可访问名称；未知状态、加载、空态、错误、只读、脏态与保存中都有明确显示。

不新增窗口布局管理器、跨设备同步或按每个资源永久记忆几何的数据库。当前已打开窗口中的用户调整需要保持。

## 4. 浮窗内导航

本 Spec 提供通用页内切换、返回和调用方页面状态保留能力；使用 stub 内容即可独立实现和验证，不依赖 S9 的浏览器。以下为 S9 集成时使用该能力的业务要求，其真实成员选择与数据测试归 S9，而非 S6 的前置依赖：

- 包管理页展示当前成员。
- “添加成员”进入独立添加页，复用 S9 的多来源浏览器，支持多选、置顶、分页、搜索／直接添加。
- 添加完成回到包管理页；取消添加不改变已保存成员。返回时保留搜索、选择、滚动和尚未提交的包编辑。
- 查看／编辑包内成员时进入该成员页面，返回恢复包管理状态。

导航与关闭不能静默丢弃未保存编辑。确需选择保存／放弃／取消时，在同一承载面处理，不用对话框套对话框。一个流程的单窗导航不限制现有任务详情与输出窗口彼此独立存在。

## 5. 内容格式与编辑器扩展

来源内容采用 S1 的 format、data、revision 契约。客户端来源展示可提供与 format 对应的预览／编辑渲染器；核心只承载状态和调用，不把 data 强制转换成 Markdown。

编辑器接收原始格式数据、只读状态、保存中状态和修改／提交回调；需要报告脏态与校验错误。保存由来源自己的 saveEdit 完成，编辑器不能自行绕过来源连接、CLI 运行或鉴权路径。

本期提供可复用的文本／Markdown编辑承载；GitHub 的标题正文、飞书任务表单和飞书文档文本块由相应来源提供呈现，遵循同一保存生命周期。现有重型编辑器继续懒加载，不进入核心 bundle。

未知结构格式可交给已注册的来源渲染器；没有渲染器时显示只读摘要／原始来源入口，不提供一个会破坏数据的“通用保存”按钮。未来富文本编辑器可以注册自己的结构呈现、校验和修改数据，无需重做包、引用、安装或浮窗接口。本期不实现完整富文本 schema、协同编辑或通用插件表单引擎。

## 6. 保存与冲突

- 保存前后状态明确：未修改、已修改、保存中、已保存、失败／冲突。
- 成功以来源真实写入结果为准；返回尚未确认时不能清除脏态。
- 检测到冲突保留本地编辑并提供重新读取／比较／返回操作。仅保存前重读的来源明确说明无法保证原子并发更新，不假造 CAS。
- 授权失效或依赖缺失保留草稿，可去配置后返回重试；不因连接界面打开而销毁编辑状态。
- 保存只更新被支持且被编辑的字段，未支持结构保持原样。来源自己的验证或 CLI 高风险确认按 S2 处理。

## 7. 现有调用方与性能

任务详情、后台任务输出的外壳迁移保持内容、实时订阅、关闭语义和显式尺寸配置。新增默认预设不能使已有填充布局变成重复滚动，也不能因为全局单窗限制关闭正在查看的日志。

窗口事件监听、portal、拖动／缩放监听在关闭时释放；隐藏来源窗口不产生持续资源扫描。可见时按来源需求刷新一次，数据事件和来源调用的生命周期继续由各自拥有者管理。

## 8. 验收与测试

- 公开 API 可被测试外部来源插件调用：open／聚焦／更新／关闭以及 disposer 生命周期有效。
- 验证集合、文档、紧凑配置预设；320／390px 窄屏、常见桌面、窗口缩小、最大化／还原、长标题和长操作文案不遮挡。
- 使用测试 stub 页面独立验证键盘操作、焦点恢复、关闭前脏态保护、浮窗内返回及调用方状态保留。真实多来源添加页及成员选择的集成验收归 S9。
- 用不属于 Markdown 的结构数据和测试编辑器，证明 data 原样传递并由来源写入；未知格式只读，不被覆盖。
- 对任务详情与输出窗运行原有测试，检查多窗口共存、流式更新不移动窗口、监听器释放与主题规则。
- Playwright 截图覆盖明暗主题、普通／加载／错误／脏态；图标和真实编辑器 chunk 正确呈现。

## 9. 集成责任

S6 拥有窗口公开 API 与编辑承载约定；S3/S4 拥有来源数据和写入语义；S9 拥有线索页面导航的业务组合。可复用组件经服务开放，不要求外部插件导入内部 FloatingWindow 文件。最终总入口与指南装配归 S9。

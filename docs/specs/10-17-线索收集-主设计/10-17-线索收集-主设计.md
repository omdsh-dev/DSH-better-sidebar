# 线索收集与来源插件体系主设计

**日期**：2026-10-17  
**状态**：原始设计归档；当前执行遵循用户已批准的 2026-10-22 修订，见[实施记录](../../plans/2026-10-22-clues-reference-flow.md)
**目标仓库**：DSH-better-sidebar

## 1. 总目标

在现有侧边栏中增加可快速浏览、组织和引用多来源上下文的「线索收集」Tab，并共同完成来源插件开放、运行依赖安装、统一浮窗改进、上下文接入、线索包分享及整体设置重整。保持本地工具的简单使用模型，不引入按会话维护的资源访问授权系统。

## 2. 范围与非目标

范围包括本地文件与 Markdown、飞书文档与任务、GitHub Issues 与 PRs；来源开放 HTTP、CLI、DSH 内 MCP 三种接入方式；包含可编辑内容的浮窗编辑、工作区绑定、`@` 引用、文件包分享和来源依赖管理。

本期不实现多人在线协作、分享服务器、完整飞书富文本编辑器、Agent 写入工具、自动安装或自动登录、进程级凭据隔离、嵌套线索包、强制包含正文策略，以及 DSH 宿主源码修改。

## 4. 依赖 DAG 与并行分组

- 第一组：S1。
- 第二组：S2、S5、S6、S7，在 S1 完成后可独立推进。
- 第三组：S3、S4、S8，在各自依赖完成后推进。
- 第四组：S9，集成全部能力并执行整体验收。

上述分组是依赖上限，不要求等待同组所有项才启动已满足依赖的下游。

并行子 Spec 只负责自身模块、测试与独立文档。宿主／客户端总入口装配、聚合导出、共享词典及公共接入指南的集中整合归 S9，不能在同一工作树由多个执行单元同时修改。具体写入范围在执行前依据实际代码划定；出现共享文件时改为串行集成，不为并行制造额外抽象。

## 5. 整体验收入口

整体验收由 [S9 的验收与验证章节](10-17-线索收集-S9-线索Tab与集成-设计.md#8-整体验收) 定义，并引用各子 Spec 的独立验收。视觉基线、后续交互修订和宿主版本验证边界也归 S9。2026-10-19 用户进一步要求融合为上小下大的分栏，现行主页面为紧凑线索包架与主要查找浏览区，同时可见且保持无高亮条；最新修订进一步改为三条紧凑包列表、按需包搜索、直接勾选资源和可逐项检查的选择清单。加入包必须明确确认，也可用所选资源直接新建包；部分失败保留未完成项目，刷新不清空查询。用户随后明确要求更彻底的交互重构，来源／类型改为常驻导航，范围类型直接单选，目标包以可搜索列表点选；每个来源保留自己的查询、分页与范围草稿。2026-10-20 用户进一步要求整体现代化、美观化，可参考 Codex Desktop／VS Code／Zed；对应修订统一为编辑器式表面、目录、工具带与紧凑列表，分页和收集确认保持稳定可达，继续保留上小下大、完整来源直接可见及无高亮条。随后用户指出图标和 UI 太素，要求参考 DSH 原生插件的多彩设计；最新修订保留上述密度与布局，补充原生文件类型图标、彩色来源、双色集合，以及来源选中／收集主操作／置顶的小面积主题色，避免再次全灰。最新用户提供 VS Code 横栏参考，要求充分使用浮窗、纵向滚动懒加载替代点击分页、替换丑陋 @ 图标并抽取可复用横栏；对应工作台以可折叠横栏分区、连续列表和任务浮窗呈现，保留原生多彩主题。具体交互与配色分工以 S9 当前修订为准。

本次七项修复已获得独立实施批准。原始子 Spec 中仍称“只读工具”的历史归属统一以 S5 当前本机只读协议为准；当前交互以 S9 最新修订为准。本文件不是实现完成报告，新鲜验证与部署状态记在实施记录。

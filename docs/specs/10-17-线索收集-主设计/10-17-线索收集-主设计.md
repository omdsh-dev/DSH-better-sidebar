# 线索收集与来源插件体系主设计

**日期**：2026-10-17  
**状态**：待用户批准  
**目标仓库**：DSH-better-sidebar

## 1. 总目标

在现有侧边栏中增加可快速浏览、组织和引用多来源上下文的「线索收集」Tab，并共同完成来源插件开放、运行依赖安装、统一浮窗改进、上下文接入、线索包分享及整体设置重整。保持本地工具的简单使用模型，不引入按会话维护的资源访问授权系统。

## 2. 范围与非目标

范围包括本地文件与 Markdown、飞书文档与任务、GitHub Issues 与 PRs；来源开放 HTTP、CLI、DSH 内 MCP 三种接入方式；包含可编辑内容的浮窗编辑、工作区绑定、`@` 引用、文件包分享和来源依赖管理。

本期不实现多人在线协作、分享服务器、完整飞书富文本编辑器、Agent 写入工具、自动安装或自动登录、进程级凭据隔离、嵌套线索包、强制包含正文策略，以及 DSH 宿主源码修改。

## 4. 依赖 DAG 与并行分组

- 第一组：S1。
- 第二组：S2、S5、S6、S7，在 S1 完成后可独立推进。
- 第三组：S3、S4、S8，在各自依赖完成后推进。
- 第四组：S9，集成全部能力并执行整体验收。

上述分组是依赖上限，不要求等待同组所有项才启动已满足依赖的下游。

并行子 Spec 只负责自身模块、测试与独立文档。宿主／客户端总入口装配、聚合导出、共享词典及公共接入指南的集中整合归 S9，不能在同一工作树由多个执行单元同时修改。具体写入范围在执行前依据实际代码划定；出现共享文件时改为串行集成，不为并行制造额外抽象。

## 5. 整体验收入口

整体验收由 [S9 的验收与验证章节](10-17-线索收集-S9-线索Tab与集成-设计.md#8-整体验收) 定义，并引用各子 Spec 的独立验收。视觉基线、后续交互修订和宿主版本验证边界也归 S9。

本主 Spec 与全部子 Spec 经用户批准后，作为 `/exec` 的输入；当前不是实现完成报告。

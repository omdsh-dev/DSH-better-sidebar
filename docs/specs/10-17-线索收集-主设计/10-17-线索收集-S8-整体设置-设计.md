**状态**：待用户批准  
**主 Spec**：[线索收集主设计](10-17-线索收集-主设计.md)  
**依赖**：[S1](10-17-线索收集-S1-来源与线索基础-设计.md)、[S2](10-17-线索收集-S2-来源运行与依赖-设计.md)、[S6](10-17-线索收集-S6-统一浮窗-设计.md)

## 1. 目标与边界

重整侧边栏整体设置，适应已有 Tab、预览器和新增来源数量；同时接入宿主新版插件设置。不同入口共享组件、设置状态与保存逻辑，不维护两份互相漂移的配置。

不是修改 DSH 设置壳、插件市场或系统密钥管理器，不把每个包的成员编辑搬进全局设置。

## 2. 信息架构

采用分组导航与紧凑设置行，宽屏导航在侧，窄屏可用分组选择或折叠导航，内容不横向溢出。

| 分组 | 内容 |
|---|---|
| 常规 | 自动打开、移动端行为等现有通用偏好 |
| 标签页 | 内置与外部 Tab 的启用及声明式专属设置 |
| 文件预览 | 预览器启用与专属设置 |
| 线索来源 | 来源显示、@ 展示、依赖、连接、来源配置和新增插件入口 |
| 外观 | 现有外观与自定义 CSS，不另加完整主题编辑器 |

已有设置的值、名称含义和保存语义不因重排被重置。不能把目前不能工作或已删除的旧设置仅凭词典 key 重新展示。

## 3. 来源管理

来源表的主要信息为：图标与名称、来源开关、@ 开关、依赖／连接状态、配置入口。缺省图标按 S1 回退；图标不可代替完整可访问名称。

- 来源开关、@ 开关分别有全开／全关按钮，作用于当前注册来源集合。批量操作通过一次配置提交处理，不产生逐行重挂。
- 按 S1 的开放映射缺项默认开，后来新增的来源默认开。批量全关不暗中创建“永远禁止未来插件”的策略。
- 线索包拥有独立的 @ 展示开关，默认开启；它不伪装成多个远程来源。
- 来源关闭隐藏浏览和 @、停止新会话自动注入该来源；已有引用仍可读，CLI／连接配置与原 @ 偏好保留。
- @ 开关只管理候选，不禁用来源读取或改变工作区绑定。
- 启用不代表已安装、已授权或立即扫描远程内容。状态明确区分缺依赖、版本不兼容、未配置、授权过期、就绪和请求失败。
- 未安装所需 CLI 不灰掉所有设置，应能进入安装或指定路径。来源插件未加载时保留已有配置及可识别的未可用信息，不伪造就绪。

本 Spec 不重新定义开关键，使用 S1 公共偏好及 S2 状态契约。

## 4. 配置、安装与授权

来源配置页使用统一页面布局及 S6 承载能力，可以显示来源专属字段。共同依赖和连接只展示一份权威状态：飞书文档／任务共享 lark-cli 连接，Issues／PRs 共享 gh。

CLI 区域提供实际使用路径、版本、兼容性、手动路径、重新检测与一键安装。安装行为完全采用 S2 的计划确认、用户级目标、进度、取消和失败处理；不能把“检测”按钮实现为业务 dry-run 或登录。

授权作为安装之外的独立动作。用户点击后展示来源白名单中的网址、二维码／人工验证码和阶段信息，完成后更新状态；取消返回配置，不清理既有有效登录态。没有用户动作时不自动登录、刷新验证或申请权限。

错误可重试，界面保留原设置；不回显 token、原始 stdout/stderr 或密钥文件内容。HTTP 来源的密码输入只提交不读回，已配置状态用宿主 describe 等无值接口；CLI 来源不读取并展示 CLI token。

## 5. 添加来源插件与依赖安装的区别

“添加来源”进入插件添加流程，可按来源类别发现扩展插件。沿用仓库现有 AddPluginModal 的插件信息与安装指引方式；若当前只能复制安装命令，不伪称已经安装成功。

来源注册完成后自动出现在列表，读取其名称、图标、能力、依赖与设置声明。没有来源能力的普通 Tab 插件不应混入来源列表。

安装一个来源插件与安装该来源需要的 CLI 是两件事。插件安装沿用 DSH/profile 机制；CLI 一键安装由 S2 在用户确认后执行，不调用 profile 包安装命令来替代系统工具安装。

## 6. 两个设置入口与保存契约

- 现有侧边栏设置入口仍可用，Tab 齿轮深链接到“线索来源”，单个来源配置可定位到该来源。
- 宿主新版插件配置席位展示相同设置主体，使用相同命名空间、修订与变更链路。具体挂载席位在目标 DSH 基线核验后选其公开支持入口，不改宿主或使用 DOM 私有补丁冒充 API。
- 命名空间用运行时 ownEntryId 自发现，兼容聚合包不同 Loader id，不硬编码包名作为设置 ns。
- 偏好使用 DSH 自己的 schemastery，收集 volatile 返回值；现有非 volatile 限额仍保留其原有重挂语义。
- 保持 settings.configure auto:false，避免宿主自动表单与定制表单重复。
- 读取走 describe 的脱敏形态，提交携带 expectedRevision；409 保留用户编辑并重读，不假装已保存。
- 不监听已知跨兄弟 fiber 不可达的 settings/document-updated 来刷新。打开、重新读取和已知本地提交后重新求值；两个入口再次打开时必须看到相同已保存值。
- 线索正文、包成员和快照不放 settings；只存偏好及非秘密配置。

## 7. 风格与可访问性

以 DSH 现有控件、字体、图标尺寸、分割线和状态文案为主，避免大块彩色卡片和深层卡片嵌套。视觉参考主色 #3388BB，通过组件边界的主题令牌表达，不全局覆盖宿主主题或散落硬编码值。

设置行布局保持标签、帮助说明和操作对齐；错误在相关行显示而不顶走整个页面。所有开关有可访问名称与键盘焦点，批量操作有明确作用范围。忙碌、失败、缺失、空列表与窄屏均有可操作界面。

工作区绑定的语义小字由 S9 的线索／包内部配置展示，这里不增加一套重复绑定管理器。

## 8. 验收与测试

- 原有偏好回归：分组重排不丢值，不改变 Tab／viewer 原有开关含义，声明式及自定义设置仍可用。
- 来源列两个批量开关、未知新来源默认开、包 @ 开关及有效状态派生符合 S1。
- 多视图共享安装状态；单击检测没有账号请求；安装与授权分别确认；手动路径优先、版本失败及授权过期可操作。
- 两个设置入口同读同写，动态 namespace、volatile 生效、409 冲突与重新打开读取都有测试。
- 隔离宿主 mount 验证新版插件设置入口真实显示，不能只通过组件单测宣称接入成功。
- 明暗主题、长来源名、无图标、第三方声明式配置、320／390px 窄屏及键盘导航无横向溢出。
- 添加插件仅提供现有支持能力，CLI 安装完成与插件安装指引状态不混淆。

## 9. 集成责任

S8 拥有设置组件和双入口接入策略；S1 拥有偏好键与来源元信息，S2 拥有依赖和授权，S6 拥有窗口。S9 负责共享词典、总入口、公共指南及全流程装配。遵循 [宿主契约](../../host-contracts.md) 与 [仓库规则](../../../AGENTS.md)。

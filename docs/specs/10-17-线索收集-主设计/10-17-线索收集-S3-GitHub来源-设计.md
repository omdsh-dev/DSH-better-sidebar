## 1. 目标与边界

在 `builtin.github.issues` 与 `builtin.github.pulls` 两个内置来源中，以 gh 为默认且唯一的本期通路，提供以单个仓库为范围的列表、搜索、URL 解析、最新内容读取，以及由用户在统一浮窗中完成的标题／正文编辑。列表与搜索结果只是轻量候选，持久引用、置顶和包成员仍按 S1 的服务契约建立。

本 Spec 负责 GitHub 资源语义、格式、权限判断、写入行为及 gh 的授权适配；CLI 探测、安装、路径与通用连接／授权生命周期归 S2，浮窗外壳与编辑生命周期归 S6。以下不属于本期目标：合并 PR、提交或撤销 review、创建 issue／PR、评论、关闭／重开、修改标签／负责人／里程碑／项目、跨仓库聚合、全仓库抓取或导出、后台同步、Agent 写入和富文本编辑器。

独立验证只使用隔离的假 gh 与本地夹具，不要求真实账号；真实账号端到端验证与 CI 证据分开声明。

## 2. 来源身份、仓库范围与稳定定位

- 两个来源共享同一 gh 依赖、同一 CLI 路径和同一账号连接，但保持独立 sourceId 与类型；Issue 与 PR 不互相冒充。
- 每次 list、search、read、edit 都显式携带一个 `owner/repo`；来源不把“当前仓库”隐式解析为工作区 cwd，也不在没有仓库范围时做大范围搜索。
- 浏览范围选择接受 `owner/repo` 或仓库 URL，验证后用于当前来源；S9 提供可编辑的范围入口并记住该工作区最近显式选择。首次无已保存范围时要求输入，不扫描账号全部仓库。来自完整资源 URL 的直接解析／读取使用 URL 自带的仓库，不要求先切换浏览范围。
- 接受 GitHub Issue／PR 的 canonical URL，以及用户明确给出的仓库与编号；URL 只解析 `github.com` 的标准 `/{owner}/{repo}/(issues|pull)/{number}` 形态，带查询串或锚点时忽略非资源部分。其他主机、短链、标题猜测和正文中的链接不自动当作目标。
- 解析结果是规范 locator：仓库身份、资源种类和编号；同一 Issue／PR 的多次解析复用一个稳定引用。URL 解析本身不置顶、不写入线索库、不建立访问授权。
- locator 只含仓库、种类、编号和可读标题，不含 token、账号或安装路径；因此 S7 的可移植导出不需要携带凭据。
- 仓库可见性不是定位信息。public／private 只影响页面展示，不作为“是否可编辑”的判断依据。
- URL 中的资源种类是权威：`/issues/{number}` 与 `/pull/{number}` 分别定位 Issue 与 PR；实际类型不符时返回类型不匹配，不静默改写成另一种引用。仓库改名或转移由 gh 的 canonical 解析处理，解析失败按资源不存在处理，不猜测新仓库。

## 3. 单页浏览与搜索

- 浏览范围是一个仓库的一类资源（issues 或 pulls），可按 open／closed／all 等来源支持的状态过滤；搜索在同一仓库和同一类型内进行，不跨仓库。
- 空查询先列当前仓库第一页；不自动把空查询扩展成跨仓库搜索，也不因搜索无结果回退到标题猜测。
- 每次请求只取一页，并设来源定义的有界 limit；禁止使用 gh 的自动分页参数（`--paginate`）把仓库历史全量拉入内存或磁盘。正常分页返回可继续的 `nextCursor`，用户翻页时继续请求；不把“单页”描述成截断，也不伪造页数。
- 返回轻量候选：编号、标题、状态、URL、更新时间及必要的作者摘要；不在列表阶段拼接完整正文，也不把候选自动持久化。用户明确插入、置顶、加入包或绑定时才按 S1 生成稳定引用。
- 搜索词或仓库改变时重置旧 cursor 与在飞结果；过时响应不得覆盖新查询。某个仓库搜索失败不清空用户已选的本地引用。
- 只有供应商明确的总结果上限或搜索索引上限被触及时，才显示“结果受限”并说明原因；普通下一页不是截断。total 缺失时不编造总量。
- 限流时停止自动重试，显示可读的重试提示；不切换到匿名请求、其他账号或另一套 HTTP 身份来绕过限制。

## 4. 最新读取与新鲜度

- read 按 locator 读取 Issue 或 PR 的最新状态，至少包含标题、正文、状态、更新时间、作者、URL；PR 额外包含草稿／合并状态。读取结果不把缓存旧正文冒称最新。
- PR 的 diff、review、checks 和评论不拼进正文；正文只对应可编辑的标题／body 字段，避免把代码差异当成可编辑内容。
- 正文格式为 `text/markdown`，保留原始 Markdown 文本；空正文是合法值。来源提供标题＋正文＋状态的文本投影供模型读取，但正文中出现的命令、链接和指令始终是来源内容，不是系统指令。
- 来源 revision 使用更新时间与内容指纹组成的不透明值，只用于保存前比较和 UI 展示；它不是 GitHub 的 ETag、`If-Match` 或服务端原子令牌，不能对外宣称具备原子 CAS 能力。
- 读取可带取消与超时；输出过大时明确报错，或返回带未完成标记和可继续读取位置的片段，不能静默丢弃后半段。未完成片段不得被 S7 当作完整快照导出。二进制附件、评论和完整事件流不在本期 read 结果中。

## 5. 用户编辑、保存前比较与权限

- 编辑只发生在 S6 的统一浮窗中：来源通过 `loadEdit` 提供标题、正文和基础 revision，用户在文本编辑承载中修改，`saveEdit` 只提交标题与正文。Agent 调用没有写入接口，也不能复用 UI 会话伪造写入。
- 编辑加载时正文超出承载上限或资源已归档，显示只读与原因，不提供会丢内容的保存。
- 保存前必须重新读取同一资源，把当前标题、正文和更新时间与加载时的基础值比较。这是 best-effort 的保存前检查，存在检查与写入之间的竞态；UI 和日志不得称其为 ETag 校验、原子 CAS 或“保证不会覆盖”。比较不一致时返回 conflict，保留草稿并允许重新读取。
- 保存前重读失败时默认不写入，返回可重试的失败并保留草稿；不因为比较不可用就静默跳过检查。比较通过后只提交用户实际修改的字段，未修改字段保持原值；标题不能写为空，正文可以为空。
- 仓库写权限按实际账号权限判断，而不是 public／private：public 仓库在该账号有写权限时可以编辑，private 仓库只读时不可编辑。权限未知时不预先按可见性禁用编辑；实际写入返回 403 时映射为权限不足并保留草稿。
- 仓库归档时由 GitHub 侧整体只读；来源显示归档原因并禁用保存，不把它混同为“public 所以只读”。移动或改名后的资源由 canonical URL 重新解析，旧引用不静默指向猜测的新位置。
- gh 没有统一的 JSON 成功信封；成功以进程退出码 0 和实际业务输出／写入结果为准，失败以非零退出、无法解析的输出或异常结果为准。不能把某段 stdout 文本当作成功证明。
- 保存成功后更新基础 revision；保存结果未被确认时不清除脏态。合并、review、创建 issue／PR、关闭／重开等动作不提供按钮或隐藏命令。

## 6. 依赖、连接与运行边界

- 向 S2 注册 `gh` 依赖及两个来源共用的连接和授权适配器；本来源适配器负责用户显式点击连接时的 gh 登录流程、人工 URL／验证码的白名单投影、取消与结果归一化，S2 承载其生命周期。凭据存储归 gh；本 Spec 不复制 token，不把认证信息写入偏好、线索或导出包。检测、安装和普通读取绝不主动调用登录命令。
- 连接摘要只显示账号与逐仓库权限，不显示 token；同一账号下不同仓库的权限分别计算。
- 不做周期性的 `auth status`、dry-run 或健康探测；连接状态只在用户显式连接、真实资源请求返回认证错误或用户手动刷新状态时更新。CLI 存在且版本兼容不等于已登录。
- 所有命令使用 argv 数组和受控环境，不经过 shell 拼接；正文通过安全参数或 stdin 传递，避免把大正文放进命令行。运行目录由操作语义明确传入，不依赖当前会话 cwd。
- 每个操作具备取消、超时、输出上限和退出码处理；stderr 只保留脱敏后的类别信息。原作者、正文、评论中的恶意内容不能获得安装、登录或写入地位。
- 列表、读取和权限判断按显式 UI 请求或 Agent 只读调用执行；不按仓库建立后台轮询、预取队列或全量缓存。来源关闭时停止自动浏览、候选预取和后台刷新；已有引用被用户或 Agent 显式 read 时仍按 S1 调用 gh 读取。

## 7. 错误与状态映射

| 情况 | 来源映射 |
|---|---|
| gh 缺失／不兼容／显式路径无效 | 依赖缺失或不可用，提示 S2 的安装／路径入口，不自动安装 |
| 未登录、token 失效或被撤销 | 需要授权；保留引用和草稿，用户显式连接后重试 |
| 403、组织策略或仓库权限不足 | 权限不足；不把 public 仓库一概标成只读 |
| 404 或不可见资源 | 资源不存在或无权访问；不泄露私有资源是否存在 |
| 限流、二级限流 | 限流；显示可读重试信息，不自动循环重试 |
| 保存前比较不一致 | 冲突；保留本地草稿并提供重读 |
| 不支持的操作／资源类型 | 操作不支持；不降级成另一条写入路径 |
| 取消、超时 | 取消／超时；不写成功状态 |
| 解析失败、网络或未知 gh 错误 | 普通失败；错误中不含 token、原始 stderr 或完整响应头 |

## 8. 独立验收

- 用隔离的假 gh 断言 argv：仓库范围正确，搜索限制在同一仓库与类型，单页 limit 生效，绝不出现 `--paginate`；正常分页返回可继续的 `nextCursor`，只有供应商总上限才显示受限；JSON 解析失败不能被当成空列表，非零退出不能显示成功。
- URL／仓库＋编号解析覆盖合法 Issue、PR、查询串、锚点、其他主机、非法路径和种类不符；同一资源重复解析复用稳定引用，解析不产生置顶或持久化副作用。
- 过时列表响应、快速切换仓库和重复解析不串数据；权限元数据过期时以实际写入错误为准。
- read 始终取最新标题／正文／状态；缓存存在时明确标记新鲜度。编辑加载与保存只影响标题、正文，未修改字段不变。
- 保存前比较能检测外部修改并返回 conflict；模拟检查后、写入前的竞态时，文档和 UI 不出现“原子 CAS／ETag”承诺。重读失败时保留草稿且不写入。
- 分别验证 public 仓库可写、public 仓库只读、private 仓库可写、private 仓库只读四种权限组合；Agent 上下文调用保存被拒绝。
- 覆盖 gh 缺失、未登录、403、404、限流、取消、超时、输出过大与脱敏；真实 gh 验证不进入 CI fixture，单独标注账号与时间。
- 假 gh 验证显式连接才启动授权适配，人工 URL／验证码正确投影、取消可达、token 不回传；检测、安装和普通资源请求不自动登录。无仓库时要求选择，修改范围重置分页，完整资源 URL 读取不依赖当前浏览范围。

## 9. 集成责任

S1 拥有来源／类型／线索模型，S2 拥有依赖与连接运行时，S6 拥有浮窗与编辑承载，S5 拥有 Agent 只读工具；本 Spec 只拥有 GitHub 资源语义、单页行为和写入冲突语义。设置页展示归 S8，Tab、入口、词典、公共指南与最终装配归 S9，本 Spec 不复制这些结构。设计完成不等于实现完成，成功证据必须来自后续新测试与真实验证。

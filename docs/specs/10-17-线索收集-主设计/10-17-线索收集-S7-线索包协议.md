# S7 `.cluepack` 协议（formatVersion 1）

**日期**：2026-10-18  
**状态**：实现契约（S7 维护）  
**主 Spec**：[S7 线索包分享设计](10-17-线索收集-S7-线索包分享-设计.md)  
**代码真源**：`src/clues/share/manifest.ts`、`zip.ts`、`export.ts`、`import.ts`、`reasons.ts`、`index.ts`

本文件记录 `.cluepack` 的线上格式、资源上限、接收方映射与 S9 可消费的接口。字段语义以本文件为准；实现自报与代码冲突时，先修代码/本文件，再改实现说明。

## 1. 归档布局

`.cluepack` 是普通 ZIP（非 ZIP64、单盘、不加密），根目录必须且只能通过绝对文件名 `manifest.json` 关联元数据：

```
manifest.json                 UTF-8 JSON，格式版本 1
content/<clue-key>.json       结构化快照（UTF-8 JSON）
content/<clue-key>.bin        原字节快照（原样保存）
```

- 条目名必须是相对路径：禁止绝对路径、盘符/UNC、`\`、NUL、`.`/`..` 段、空段、首尾空白段；名长上限 1024 字节。
- 目录条目不承载数据；符号链接、FIFO/套接字/设备等非普通文件模式、重复条目（含 Unicode NFC 等价名）一律拒绝。
- 解压只发生在内存中，条目名从不当作落盘路径；当前实现不做任何提取。
- 大小写不同的两个名字按 ZIP 语义仍是不同条目（插件不提取，故不做文件系统大小写折叠）；Unicode NFC 等价名会被当作重复拒绝。
- 读取只信 central directory 列出的条目：local-only 残留、central directory 之外的字节或共享 payload 都不会被解压，也不形成落盘路径。
- 读取时逐个条目校验 CRC32、声明大小与 `content/` 快照的 SHA-256；任何缺失/不匹配都在第一次写库前失败。
- 写入端与读取端共用同一组上限，插件导出的归档必定能被自己的导入器接受。

## 2. manifest

根对象字段：

| 字段 | 语义 |
|---|---|
| `formatVersion` | 整数，当前唯一支持值 `1`；其它值以 `unsupported` 明确拒绝，不猜测新版本 |
| `format` | 固定 `"dsh-cluepack"` |
| `exportedAt` | ISO 时间戳 |
| `mode` | `"references"` 或 `"snapshot"`；`references` 中出现任何快照即拒绝 |
| `sources` | 来源署名记录，键为包内 `sourceKey` |
| `clues` | 线索记录，键为包内 `clueKey` |
| `packs` | 包记录，成员为有序、去重、不嵌套的 `clueKey` |
| `issues` | 与包内对象关联的失败/缺失记录 |

未知扩展字段在每一层都被忽略；校验器只复制文档化字段，因此手工构造的 manifest 不能把任意数据塞进导入记录。包内键只描述“这一次归档内部”的关系，永远不充当接收方运行时 id。

### 2.1 source

```json
{
  "key": "source-1",
  "sourceId": "builtin.files",
  "pluginId": "dsh-better-sidebar",
  "name": "Local files",
  "transport": "files",
  "typeIds": ["builtin.files.markdown"]
}
```

`sourceId` 是接收方匹配来源的唯一稳定标识；`pluginId`/`name`/`transport`/`typeIds` 只用于展示与缺失诊断。不得携带 token、cookie、私钥、CredentialRef、环境变量秘密或发送方连接认证配置。

### 2.2 clue

```json
{
  "key": "clue-1",
  "sourceKey": "source-1",
  "typeId": "builtin.files.markdown",
  "title": "设计笔记.md",
  "portable": { "portable": true, "locator": { "...": "来源定义的可移植地址" } },
  "snapshot": { "...": "可选，一条 clue 最多一份" }
}
```

- `portable.locator` 是来源产出的、无凭据的可移植定位信息；`portable:true` 时 locator 必须非空，否则 manifest 无效。
- `portable:false` 表示来源明确拒绝可移植地址；`reason` 是稳定原因，不可是原始认证错误。导出端只写 `reasons.ts` 中的固定文案；来源 `portable()` 返回的原始 `reason`、本地 unresolved 行的原始 `reason` 都不会被复制进 manifest。代码无法识别的旧 reason 在导出边界替换为固定 fallback（`the reference is unresolved on this machine`）。
- 外部绝对路径只作为 `portable:false` 的显式提示（hint）出现，接收方不会自动打开同路径。
- 快照是每条 clue 的可选字段，不是顶层映射。

### 2.3 snapshot

```json
{
  "path": "content/clue-1.json",
  "encoding": "json",
  "mediaType": "application/json",
  "format": "text/markdown",
  "bytes": 1234,
  "sha256": "64-lowercase-hex",
  "fetchedAt": "2026-10-17T00:00:00.000Z",
  "sourceVersion": "rev-1",
  "assets": [
    {
      "path": "content/clue-1.asset-1.bin",
      "kind": "download",
      "mediaType": "image/png",
      "bytes": 4567,
      "sha256": "64-lowercase-hex"
    }
  ]
}
```

- `path` 必须位于 `content/` 下并通过 ZIP 条目名规则；`encoding` 仅为 `json`/`raw`。
- `json` 正文是 `{ format, data, text? }`，`format` 必须与 manifest 一致；`raw` 正文按原字节保存，导入后以 base64 JSON 传输包装存入 S1（传输编码不是内容改写）。
- `assets` 可选，保存同一次 `read` 返回的其余原始资产；每个资产同样在 `content/` 下、有真实字节数/SHA-256。没有资产时该字段省略。一次 read 的正文、第一个原始资产与全部额外资产都会进入归档；某项读不到时整条线索写 issue 并令导出 `complete:false`，不会静默只取第一个资产。
- `bytes` 是归档内主正文的实际字节数，`sha256` 是该字节的小写十六进制摘要，`fetchedAt` 是真实获取时间。
- 导入后由 S1 生成 `snapshotId`，归档路径不成为运行时标识。多 part 快照在 S1 的 JSON-only content 中投影为带版本标记的 bundle（`{kind:"cluepack-snapshot-bundle", version:1, primary, assets}`）；离线再分享时导出端识别同一标记并逐字节还原主正文与资产。

### 2.4 issue

```json
{ "target": "clue", "key": "clue-1", "category": "rate-limited", "reason": "the source rate limited the export" }
```

`target` 为 `clue` 或 `pack`，`key` 必须指向包内对象；`category` 若存在必须是固定 ClueError 类别。导出端只写固定类别含义的安全文案，**绝不复制来源错误的原始 message**（本地绝对路径、私有 URL、认证错误都可能出现在那里）。导入端把 `manifest.issues` 单独返回为 `manifestIssues`，不把它们算成本地提交失败。

## 3. 两种模式

- **references**：只写 `manifest.json`，不调用来源 `read`，不携带正文或缓存。
- **snapshot**：逐 clue 调用来源读取，记录真实 `fetchedAt`、字节数、SHA-256 与可用 revision；本地文件资产保留原始字节；结构文档保存来源声明的 `format` 与 JSON 投影，不通过 Markdown 回写。
- **本地文本的字节边界**：`builtin.files` 的文本 read 返回已解码文本且不附带 raw asset（BOM/UTF-16/CRLF 已被来源解码）。此时 S7 按 Spec §4 的“结构文档保存来源声明的格式与可用文本投影”分支保存 UTF-8 JSON 投影，原文件编码/BOM 不可恢复；测试 `clues-share-roundtrip.spec.ts` 的 UTF-16LE BOM 用例固定了该行为。若未来 S1 的文本 read 附带原字节 asset，则走 raw 资产路径并保留字节。
- 某一项失败时写入 issue、`complete:false` 并在下载响应头 `x-cluepack-complete: false` 暴露；取消/超限直接拒绝，不产出可被误认成完成品的归档。
- 已解析 clue 的 live read 失败但本地有旧快照时，归档会带上旧快照**并写入该失败类别与旧 `fetchedAt` 的 issue**，不会静默返回完整成功；导入预览通过 `manifest.issues` 与 `snapshotFetchedAt` 展示这一点。
- 未解析但拥有快照的 clue 仍可离线再分享；没有快照时写 `source-missing` issue。

## 4. 资源上限

| 限制 | 默认值 |
|---|---|
| manifest 字节数 | 4 MiB |
| `sources` / `clues` / `packs` / `issues` 各数组元素数 | 10,000 |
| 可移植 locator JSON 嵌套深度 | 64 |
| ZIP 条目数 | 10,001 |
| 单条展开大小 | 32 MiB |
| 全部条目展开大小 | 128 MiB |
| 归档字节数 | 64 MiB |
| 条目名字节数 | 1,024 |
| `clues.share.importPreview`/`import` 的 JSON base64 归档 | 512 KiB 解码后 |
| raw import 路由请求体 | 64 MiB |

条目数、展开总量与 manifest 大小在读取/组装时预检；归档大小由 ZIP writer 用**压缩后**的精确大小检查，不能用“展开字节数”当作归档下界（deflate 文本可远小于展开值）。超出上限一律 `invalid-request` 并说明原因。

## 5. 接收方映射

接收方永远不执行包内命令、不安装插件/CLI、不发起授权、不写回原文件。

1. 来源已安装、类型存在、地址可移植：`clues.ensure` 复用同资源的本地 clue，不覆盖现有 live locator/title/读取模式；快照作为独立 snapshot 关联。
2. 来源缺失或类型缺失：`clues.importUnresolved` 保留为普通 unresolved clue，read 返回 `source-missing`，快照仍可独立读取。
3. 本地文件 workspace 相对地址：把 `workspaceId` 换成接收工作区。若路径 dialect 与主机不同，**保持 unresolved** 并给出可读 reason（不会假装 live 然后读取失败）。
4. 外部绝对路径：保持为显式 `portable:false` 提示，必须由用户显式 remap。
5. 显式 remap：JSON 安全列表
   ```json
   [{ "clueKey": "clue-1", "locator": { "...": "接收方地址" }, "connectionId": "可选" }]
   ```
   - `connectionId` 必须等于本机来源当前暴露的连接；同名不同账号不会被假定为同一连接。S1 当前按 sourceId 至多一个活动 descriptor；真正的多连接选择属于 S1/S2 seam，S7 对不可用连接给出可读 unresolved reason。
   - 再次导入同一包并显式 remap 时，会先按包内 hint 找到已存在的 unresolved 行并原地更新其 portable hint，再 `ensure` 解析成同一 clue id，避免“旧 unresolved 行永久孤立”。
   - 若目标地址已经属于另一条 live/unresolved 行，S1 没有合并/删除 API：导入端不 seed 旧行，写 `conflict` issue 并返回 `partial:true`/`complete:false`，不会静默 `complete:true` 地留下孤儿。
   - `portable:false` 的 workspace 形式 hint 在跨工作区导入时重定根到接收工作区后再存入 unresolved 行（仍保持非 portable）；外部绝对路径保持原样。这样再次导入同一包仍能按地址复用同一行。
   - 无地址可关联的 unresolved 行（manifest 连 hint 都没有）无法被稳定关联，重新导入会新建 clue；这是 S1 没有“按包内键 remap 已存在行”API 的已知残差。

跨平台：locator 保留写入时的 `posix`/`win32` dialect，绝不会用另一方言的 `node:path` 重新解释；非本机 dialect 一律 unresolved，直到用户显式 remap。

## 6. 导入/导出事务语义

- 预览只读本地注册表/库与归档，不读来源、不安装、不授权、不写库。
- 校验全部内容大小/SHA/路径在第一次写之前完成。
- 第一次写之前取消：抛 `cancelled`，目标区域不动。
- 第一次写之后取消/失败：S1 没有跨对象事务，无法回滚；返回显式 partial 结果（`complete:false`、`partial:true`、`requiresAcceptance:true`、已提交对象与原因），不伪装成功也不裸抛掩盖已写行。remap adoption 的 seed 写入（`importUnresolved` 原地更新旧 unresolved 行）同样计入已提交写：seed 后取消会返回 partial，并在原因中注明原地更新数，不会裸抛 `cancelled`。
- 全部写完后才观察到取消：返回正常结果并置 `cancelled:true`，避免调用方重试产生重复包。
- 发送方的 `manifest.issues` 单独返回，不改变接收方本地提交的 `complete`。
- **已知范围残差**：S1 当前没有跨对象事务、删除或合并补偿。提交失败/首次写后取消时，已写出的 clue/snapshot/pack 无法真正回滚到“目标区域未写出”的状态；S7 只能返回显式 partial 结果并列出已提交对象。Spec §5/§7 的严格原子性验收需要 S1 提供事务或补偿 API 后才能完全满足，本协议不把它伪装成已实现。

## 7. S9 接口

JSON API（`clues.registerApi`）：

| 方法 | 输入 | 输出 |
|---|---|---|
| `clues.share.exportPreview` | `{ workspaceId, mode, packIds?, clueIds? }` | 导出预览 |
| `clues.share.exportInspect` | 同上 | 将要携带的精确 portable 引用（不读正文） |
| `clues.share.exportProgress` | `{ exportId }` | 进度/终态（含 `complete:false` 的 issues），未知 id 返回 `null` |
| `clues.share.importPreview` | `{ workspaceId, archiveBase64, remap? }` | 导入预览（含每项 `willBeUnresolved`/`unresolvedReason`/`snapshotFetchedAt`） |
| `clues.share.importProgress` | `{ importId }` | 进度/终态（partial 结果含 issues/reasons），未知 id 返回 `null` |
| `clues.share.import` | `{ workspaceId, archiveBase64, remap?, importId? }` | 导入结果（适合 ≤512 KiB 小包与自动化；remap 不受 URL 长度限制） |

raw 路由（S9 用 `ctx.webServer.register` 挂载，全部 exact POST）：

```
/sidebar/clues/share/export-preview   JSON body → JSON
/sidebar/clues/share/export           JSON body → application/zip
/sidebar/clues/share/import-preview   ZIP body  → JSON   (?workspaceId, ?remap)
/sidebar/clues/share/import           ZIP body  → JSON   (?workspaceId, ?remap, ?importId)
```

- export body 可带 `exportId`，响应头 `x-cluepack-complete/issues/clues/packs/snapshots` 与 `clues.share.exportProgress` 对应。
- import 可带 `importId`；路由把 `onProgress` 写入 `clues.share.importProgress`，并在 partial 结果时写终态 `outcome`。
- 响应连接关闭会转发为 AbortSignal；四个 raw route 都在读取请求体**之前**安装 close 监听，并在读完后复核 signal，因此上传期间断开不会被漏掉。导入在第一次写前取消时返回 499 `cancelled`，写完后的取消按 §6 返回 partial/`cancelled` 结果。
- 大体积导入/导出只走 raw 路由：通用 `/sidebar/api` JSON dispatcher 有 1 MiB 请求体上限。

## 8. 进度与并发

- `exportProgress`/`importProgress` 是有界的内存频道：**终态**条目按 TTL/LRU 淘汰；仍有在飞请求的键（active）不淘汰、不因 TTL 过期，符合仓库“模块级 Map 的有在飞请求的键不淘汰”约定。active 条目较多时允许短暂超过 `maxEntries`，任务结束后再回落到上限。
- 进度条目不写入 manifest，也不改变归档内容。

## 9. 兼容与版本

- `formatVersion` 是整数；本插件只写 1、只读 1。
- 未知扩展字段忽略；未知版本、外格式、references 模式夹带快照、重复键/成员、悬空引用、非法摘要/大小/路径全部拒绝。
- 修改既有字段含义、内容编码或上限属于协议变更，必须提升 `formatVersion` 并同步本文件与测试。
- `snapshot.assets` 是 v1 的**可选增量字段**：旧读取器按“未知扩展字段忽略”只使用主正文，新读取器完整保留多 part；既有字段含义未变，因此保持 `formatVersion: 1`。若未来需要改变主正文的编码语义，才提升版本。
- 公共包子路径 `dsh-better-sidebar/clues` 尚未导出 `installCluesShare`/`createCluesShareRoutes`（属 S1/package owner 范围）；S9 可在 `src/index.ts` 内相对 import，外部消费者暂时无法从公共子路径使用。

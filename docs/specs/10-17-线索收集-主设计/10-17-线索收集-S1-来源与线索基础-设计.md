# S1 来源与线索基础设计

**日期**：2026-10-17  
**状态**：待用户批准  
**主 Spec**：[线索收集主设计](10-17-线索收集-主设计.md)  
**依赖**：无

## 1. 目标与边界

建立所有内置及外部来源共用的注册、领域模型和持久访问基础，并提供本地文件／Markdown 参考来源。来源、线索类型、线索包、编辑器不是同一个概念。

本 Spec 不实现远程来源、CLI 安装器、聊天输入框、分享 ZIP 或 Tab 页面；对应职责见主 Spec 索引。此基础必须能用内存来源与本地文件独立验证，不依赖第三方账号。

## 2. 领域模型与归属

| 对象 | 必要语义 |
|---|---|
| 来源 Source | 具有稳定 sourceId、显示名称、顺序、来源插件身份、类型清单和操作能力的提供者；运输方式不等于内容类型 |
| 线索类型 Type | 具有命名空间内稳定 typeId；描述内容格式与编辑能力；同一来源可以提供不同类型 |
| 线索 Clue | 一个原始资源的稳定引用，具有 id、sourceId、typeId、来源定义的 locator、标题和归属工作区；不是默认复制的正文 |
| 线索包 Pack | 具有 id、名称、归属工作区及有序成员引用；仅为多个线索的集合，不支持嵌套包和独立成员权限 |
| 置顶 Pin | 工作区与线索的常用入口关系；与线索是否可读无关 |
| 工作区绑定 Binding | 工作区与线索或包的自动引用关系；只决定新会话提供哪些引用，不是访问权限 |

- 工作区拥有线索库和包；会话按需引用。其他工作区可以通过显式选择引用现有线索／包，不必复制原始资源。
- 工作区身份采用宿主稳定 workspaceId。工作目录变化不改变已保存线索的原始资源定位；不能把当前 cwd 当作旧引用的解析根。
- 删除并重新建立一个工作区不会静默继承已删除 workspaceId 的绑定。数据不因工作区从侧栏移除而自动清空；重新关联是显式动作。
- 同一资源可属于多个包，包内成员去重。移除成员、取消置顶、解除绑定都不删除原始资源或稳定引用。
- 包删除是明确动作：解除其绑定并使该包标识返回已删除；它不级联删除成员。重命名包不改变标识。

## 3. 稳定引用与持久化

线索与包的 id 不使用会话 id、缓存 id、CLI 页码、临时下载链接或认证 token。已插入的引用不因闲置、重启、上下文压缩、翻页或取消置顶而失效。

来源负责规范化 locator 和判定资源相等性。重复解析同一资源时复用原引用；分页／搜索结果可以是轻量候选，只有插入、置顶、加入包、绑定或导入等持久使用发生时才确保稳定引用存在。不能把每次浏览的整个远端列表永久写入线索库。

持久数据保存在插件用户数据目录，按工作区归属组织，由服务端权威管理。不能放在浏览器 localStorage、聊天日志或 settings 偏好大字段中。正文缓存与稳定引用分离；缓存可淘汰，引用不得按 TTL 淘汰。

分享导入的内容是独立持久快照，不是可淘汰缓存。基础存储为每份快照分配稳定 snapshotId，关联 clueId、format、内容／资产、获取时间、可用的来源版本和完整性状态。同一 clueId 可关联多份快照；导入不能覆盖其 live locator 或改变旧引用的默认实时读取。快照读取由核心的本地存储提供，不依赖原始来源插件、CLI 或账号。显式删除导入资产之外，不因来源禁用、闲置或缓存清理而淘汰；S7 拥有导入归属规则，S5 拥有快照引用与工具选择。

包、置顶与绑定的修改具有修订检查：并发编辑不能静默覆盖他人的新成员或绑定；冲突时保留本地输入并返回 conflict。落盘失败不能返回成功或先丢弃旧数据。内部存储格式与具体文件划分留给实现，不新增数据库服务。

## 4. 公共来源契约

### 4.1 两侧服务与生命周期

- 新增宿主侧 Cordis 服务 `betterSidebarClues`，提供来源／类型注册与统一资源操作。它不是现有仅在 client half 存在的 `betterSidebar` 服务。
- 客户端通过现有 `ctx.betterSidebar` 的 `clues` 扩展面消费来源目录、资源操作及注册客户端展示；不 value-import 其他来源插件。
- 公共类型以包的 `clues` 子路径导出；现有主入口及 client/service 兼容行为不得破坏。聚合出口与总入口装配由 S9 统一接入。
- 来源注册返回 disposer；通过 Cordis inject/effect 等待依赖并随 owning fiber 卸载。重复 sourceId／typeId 明确拒绝，不靠顺序覆盖。
- 卸载来源只移除运行能力，不清除其引用、置顶、包成员和连接配置；同标识来源重新注册后可恢复解析。

### 4.2 元信息与能力

每个来源声明稳定身份、名称、图标展示标识、插件身份、顺序、类型、运输种类及能力。运输种类为 HTTP、CLI、DSH 内 MCP；内置本地来源直接使用文件服务，不伪装成外部命令。

客户端来源展示的 icon 沿用 TabDescriptor 的 ReactNode 或按 size 渲染图标的约定。来源可提供品牌图标，没有时使用类型图标回退；图标必须遵循宿主尺寸与主题。名称不能只剩图标而不可访问。宿主目录只传可序列化元信息，React 渲染器由对应客户端插件注册，不经过 JSON 传输。

| 操作 | 契约 |
|---|---|
| resolve | 解析用户提供的路径、URL 或资源标识，返回规范候选；不通过模型猜测来源，不因解析而自动置顶 |
| list（可选） | 在来源声明的范围内逐页列举，无搜索词也可用；输入范围、cursor、limit，返回 items、nextCursor 及可选 total |
| search（可选） | 在相同范围内搜索，采用同一分页结果；不支持时明确缺失，不能用全量下载假装搜索 |
| read | 按稳定 locator 读取当前内容；可显式分页，不静默截断，也不能把缓存旧内容冒称最新 |
| loadEdit／saveEdit（可选） | 提供来源自己的编辑文档并提交修改，见第 5 节 |
| portable（可选） | 导出／恢复无凭据的可移植 locator，供 S7 使用；不提供时保留未解析引用，不随意执行安装或命令 |

分页 cursor 是来源不透明值。来源切换、查询／范围改变时重置 cursor；total 缺失时 UI 不编造总页数。来源可以只支持 resolve/read，也可以支持 list/search；不能列举的来源依然可使用置顶和搜索／直接添加。

每次操作接收取消信号；执行上下文明确区分 UI 请求与 Agent 只读调用，按需提供调用会话信息给宿主集成，不把它作为资源访问白名单。S2 定义运输、依赖与授权执行边界。

### 4.3 内置身份

本期固定以下内置 sourceId，避免下游各自命名：`builtin.files`、`builtin.github.issues`、`builtin.github.pulls`、`builtin.feishu.docs`、`builtin.feishu.tasks`。

线索包属于统一的本地包库，不是每个远程来源的一种独立包。其目录／展示身份使用保留标识 `builtin.packs`，不能被第三方来源占用。该标识不是宿主 inputTriggers 的 source name；S5 拥有稳定的聚合 codec 名称，包目录 `builtin.packs` 对应 `better-sidebar:packs`，业务线索来源共同使用 `better-sidebar:clues`。两层标识不得互换用于 codec 查找。

## 5. 内容与编辑扩展

统一读结果至少能够表达：内容 format、来源数据 data、可选 revision、fetchedAt、live／snapshot 新鲜度及供模型读取的文本投影。二进制资源使用明确的资产描述或可读取入口，不强行解码成字符串。

- `text/plain`、`text/markdown` 是本期可用格式，但不是核心唯一格式。
- 来源可声明命名空间化的结构格式，并通过客户端展示描述符提供对应预览／编辑器。复杂 data 由来源定义和校验，核心不把它转成 Markdown 再保存。
- 编辑加载与保存使用相同 format 和来源定义的数据；baseRevision 为不透明可选值。来源须说明有原生条件更新、仅保存前检查，还是无并发保障。UI 不能把「保存前重读」宣传成原子 CAS。
- 保存只修改用户编辑的内容，保留未知或不可编辑结构。源端检测冲突时返回 conflict 并保留草稿。
- S6 拥有浮窗和编辑器承载契约；来源拥有格式、校验和真实写入。未来富文本编辑器可以替换呈现层而不更换线索标识、包模型或上下文接口。
- 类型允许向后兼容地增加有命名空间的扩展元信息；本期不增加“强制包含内容”字段、开关或执行策略。

## 6. 偏好与开关语义

公共偏好键为 `clueSourcesEnabled`（sourceId→boolean）、`clueSourcesMentionEnabled`（sourceId→boolean）、`cluePacksMentionEnabled`（boolean）。来源映射缺项视为 true，包的 @ 开关默认 true，内置来源默认全开。字段进入现有 volatile 偏好链路，不因普通展示开关重挂插件。

- 来源关闭：不展示其浏览和 @ 入口，不自动列举／搜索，S5 不在新会话自动注入该来源；已有引用仍可通过统一 API 读取。
- @ 开关只控制输入框候选，不控制 Tab 浏览、历史读取或明确配置的工作区绑定；来源关闭时有效 @ 状态仍为关闭，保存的 @ 偏好不被抹掉。
- 重新打开来源恢复原置顶和绑定配置。
- 真正停用／卸载来源插件、CLI 不可用或授权失效可以导致读取失败，但引用记录保留并显示具体原因。
- 连接、CLI 路径和来源专属非秘密配置使用现有 pluginSettings 扩展；CLI 凭据由 CLI 管理，HTTP 自有秘密使用宿主 credentials，不混入偏好或线索记录。

## 7. 本地文件参考来源

复用现有文件服务、编码检测、LF 请求及服务端原格式还原机制。支持工作区文件浏览、搜索和路径解析；允许用户显式选择工作区外的文件，不重新加入被仓库移除的目录围栏。

本地 locator 保存稳定解析根和路径语义。普通工作区相对路径跟归属工作区解析；外部绝对路径保留平台方言。Windows 与 POSIX 路径按入参平台处理，不能用运行宿主的平台路径函数猜另一平台的路径。

Markdown 与可编辑文本可编辑；二进制及现有只读格式提供预览／下载或打开原始资源，不伪装可编辑。保存沿用既有变更检测，外部修改时明确冲突。跨机恢复本地 locator 的规则由 S7 定义。

## 8. 错误与运行约束

统一错误至少区分：来源缺失、依赖缺失／不兼容、需要授权、权限不足、资源不存在、操作不支持、限流、冲突、取消和普通失败。来源原始 stdout/stderr、Authorization、token、环境变量秘密不直接进入错误、日志或模型返回。

不引入每会话许可表、访问票据或历史引用过期机制。沿用宿主本地／已认证 Web 请求边界，所有自有 HTTP/WS 接入使用现有 Connection admission。服务端插件之间仍是可信代码边界，不宣称进程级密钥隔离。

注册目录、浏览缓存及在飞请求按来源／资源共享；模块级缓存有上限，取消订阅和卸载释放资源。不得为每个 keepMounted Tab 建立一套后台扫描。

## 9. 验收与测试

- 内置和外部测试来源使用同一注册 API；重复注册拒绝、依赖延迟到达、卸载／重载及未解析引用恢复均有契约测试。
- 重启后线索／包 id 不变，工作区切换、长时间闲置、取消置顶和解除绑定不影响旧引用读取。
- 同一资源去重、包内去重、跨包复用、成员移除不删资源、包删除不删成员及并发冲突均可独立验证。
- 验证缺失 list/search 能力、未知 total、分页取消、query 改变及错误归一化。
- 用一个非文本结构格式及测试编辑器证明 core 不依赖 Markdown；未知结构经加载／提交后不被核心篡改。
- 本地文件验证现有编码／行尾、外部路径、跨平台路径、只读格式和冲突语义；按仓库契约运行相关文件与主题测试。
- 成功证据来自新测试结果；本 Spec 本身不声称已实现。

## 10. 集成责任

S1 提供可独立使用的服务、模型、注册契约和本地来源。其他子 Spec 依赖这些契约，不复制存储或来源身份逻辑。共享入口和公共指南总装配交 S9；实现前遵循 [仓库规则](../../../AGENTS.md) 与 [宿主契约](../../host-contracts.md)。
